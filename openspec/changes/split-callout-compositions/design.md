# Граница категорий

`callout` оформляет штатную структуру и стандартные типы. Обычные вложенные callout, сворачивание, списки и таблицы внутри выноски сами по себе не являются специальным синтаксисом.

`composition` требует пользовательского типа (`ticket`, `qna`, `decision` и т. п.) либо специального протокола ролей/структуры содержимого. В текущем каталоге все такие приёмы имеют пользовательские типы. Простое совпадение слова «композиция» в названии приёма не является основанием переноса. Стандартные quote-callout в категории quote не требуют нового синтаксиса и остаются там.

ID и папки приёмов сохраняются ради ссылок. Меняются category, тег, group и target. `previousTargets` явно разрешает перенос собственного маркированного блока при применении. Повреждённые и дублированные блоки отклоняются; ручной CSS сохраняется. До обновления ранее установленный CSS остаётся в старом файле и продолжает работать.

Добавление composition в конец GROUPS сохраняет все существующие имена файлов. Миграция structure=2 добавляет отсутствующие модули, сохраняя старые записи manifest и содержимое существующих файлов.

Проверка composition-catalog охватывает все каталоги приёмов, включая вложенные: специальные типы в CSS и Markdown, согласованность карточек и hack.json, новую страницу и ссылки в общем атласе. Исторические отчёты в ! defaults не являются текущим реестром категорий.
