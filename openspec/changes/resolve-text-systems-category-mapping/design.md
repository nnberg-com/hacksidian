# Общая схема

Публичный параметр остаётся аннотированной CSS Variable типа select. Соседняя `@hacksidian-variants --variable` содержит `@variant value` с производными `--hacksidian-*` переменными. Каждая строка таблицы обязана иметь один и тот же набор имён; запрещены селекторы, ресурсы и изменение публичных параметров. Компилятор вставляет выбранную строку в родительский CSS-селектор. CSS вне таблиц не меняется. В установленный сниппет попадает обычный CSS без служебных at-rules.

Это расширение формата recipe.css, а не отдельная база параметров. Оно используется одинаково при включении, обновлении, обычном и expanded-предпросмотре. UI/чат сохраняют только публичное значение существующим updateParameter и Vault.process.

expanded.md — авторский Markdown с произвольными пояснениями и блоками hacksidian-expanded. Каждый блок содержит JSON-объект входных значений обычных параметров. Неуказанные поля используют актуальные значения приёма. Пример вычисляется в памяти; кнопка выбора сохраняет только перечисленные поля одной транзакцией с проверкой конфликтов. Поддерживаются и обычные числовые/цветовые/текстовые параметры без таблиц. Файл не имеет тега техники и не попадает в поисковый каталог как отдельный приём.

Генераторы сохраняют текущий выбор, если он ещё существует. Если значение исчезло, генерация останавливается, требуя явной миграции. Таблицы текстовых систем и первичные цветовые данные хранятся в tools; итоговые источники и адаптации доступны пользователю рядом с карточкой.

hack.json сохраняет format:2 и добавляет необязательное replaces: список устаревших ID. Удаление старых применённых блоков выполняется только при явном применении нового приёма, строго в целевом модуле. Повреждённые маркеры вызывают ошибку до записи. Исходные старые карточки удаляются из репозитория; удалённый индекс потребует обычной отдельной синхронизации.
