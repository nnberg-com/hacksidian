## Why

В продукте принято правило: **одна категория — одна страница в песочнице — один CSS**. Новая категория «Текстовые системы» (`text-systems`) выпадает из этого соответствия.

Статус: отложенная продуктовая проблема, зафиксированная по просьбе пользователя. Решение не выбрано; реализацию сейчас не начинать.

Текущее состояние:

- В атласе создана отдельная категория «Текстовые системы» с десятью принятыми приёмами.
- Отдельной страницы этой категории в песочнице нет. Живые примеры в карточках не заменяют страницу песочницы.
- Категория ссылается на `hacksidian-04-text.css`, а её приёмы используют `target: g-text`, общий с категорией «Текст». Собственного CSS категории нет.
- Фраза в карточке категории «отдельный CSS-модуль не требуется» описывает сделанную реализацию, но не является согласованным продуктовым исключением из правила.

Таким образом, расширение атласа ввело исключение без решения о том, как комплексные текстовые системы должны вписываться в продуктовую структуру.

## What Changes

Пока фиксируется только проблема для последующего обсуждения. В дальнейшем нужно определить место текстовых систем в соответствии «категория — страница песочницы — CSS» и согласовать поведение продукта. Конкретное изменение структуры, интерфейса или CSS пока не назначено.

Открытые вопросы:

- Как представлять комплексную систему, одновременно меняющую основной текст и заголовки, в существующем делении на категории?
- Какое соответствие категории, страницы песочницы и CSS должно действовать для текстовых систем?
- Какие изменения навигации, примеров и применения приёмов потребуются после продуктового решения?
