## Context

Hacksidian рекомендует существующие приёмы из поискового каталога. Пользователь хочет в будущем задавать визуальный образец скриншотом. Это отложенная возможность, не разрешение на реализацию сейчас.

## Goals / Non-Goals

Цель — найти приёмы с похожими видимыми свойствами. Автоматическое применение, восстановление исходного CSS и точное копирование изображения исключены.

## Decisions

Предварительная схема: выбранное вложение и пояснение → описание видимых признаков моделью с поддержкой изображений → поиск по текстовому каталогу → проверка ID и объяснение соответствия. Это гипотеза для проверки качества, а не выбранная окончательно архитектура. Вариант объединённого запроса с изображением и File Search также оценить перед реализацией.

Сохраняются ручное применение приёмов, независимые языки интерфейса и содержимого, существующий учёт расходов. Во время планирования изображения в API не отправляются.

## Risks / Trade-offs

Внешнее сходство не доказывает использование конкретного CSS или темы. Текстовый индекс может не содержать достаточных визуальных описаний. Сначала проверить на небольшом наборе согласованных скриншотов, прежде чем расширять индекс.

## Open Questions

- Форматы и размеры вложений, необходимость обрезки перед отправкой.
- Хранение вложения в локальной истории и срок его хранения.
- Критерии приемлемого сходства и примеры, выбранные пользователем для проверки.
- Поддерживаемые модели, стоимость и достаточность существующего поискового каталога.
