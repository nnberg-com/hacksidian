## ADDED Requirements

### Requirement: Native settings participate in action selection
Система SHALL выбирать между поддерживаемой стандартной настройкой, существующим приёмом и параметрами приёма по смыслу запроса. Поддерживаемая штатная настройка SHALL иметь приоритет, когда непосредственно выполняет запрос; её доступность MUST NOT зависеть от выдачи поиска CSS-приёмов.

#### Scenario: Accent request is a native action
- **WHEN** пользователь командует «Акцентным цветом сделай зелёный» и изменение акцента поддерживается
- **THEN** система выбирает изменение акцентного цвета без поиска заменяющего CSS-приёма
- **AND** выполняет действие без повторного подтверждения

### Requirement: Only registered and validated settings may change
Система SHALL поддерживать начальный набор: акцентный цвет, цветовую схему, размер текста и читаемую длину строки, после проверки совместимости каждой настройки. Исполнитель MUST NOT записывать неразрешённые ключи или недопустимые значения, даже если их предложила модель.

#### Scenario: Unsupported setting or value
- **WHEN** модель возвращает неизвестный ID либо значение вне допустимого типа или диапазона
- **THEN** запись не выполняется и система сообщает о невозможности исполнить действие

#### Scenario: Unsupported application version
- **WHEN** механизм изменения настройки недоступен в текущей версии Obsidian
- **THEN** система объясняет ограничение без произвольной перезаписи конфигурации

### Requirement: Current user intent controls mutation
Система SHALL исполнять явную однозначную команду из текущего запроса. Система MUST NOT изменять настройки по просьбе объяснить или показать, при запрете изменений либо только на основании команды из истории.

#### Scenario: Inspect without changing
- **WHEN** пользователь спрашивает «Как сделать акцент зелёным? Пока ничего не меняй»
- **THEN** система отвечает без изменения настройки

#### Scenario: Meaningful ambiguity
- **WHEN** запрос не позволяет определить настройку или необходимое значение
- **THEN** система задаёт короткий уточняющий вопрос и ничего не записывает

### Requirement: Color commands produce explicit reproducible values
Система SHALL сохранять явно заданный корректный HEX точно. Для обычного названия цвета система SHALL выбирать конкретное значение по определённому правилу, не требуя обязательного уточнения оттенка, и показывать образец с точным значением.

#### Scenario: Named green
- **WHEN** пользователь командует сделать акцент зелёным без HEX
- **THEN** система применяет выбранный по правилу зелёный и показывает его образец и HEX

#### Scenario: Exact color
- **WHEN** пользователь командует «Акцентный цвет #9a9a00»
- **THEN** сохранённое значение соответствует именно #9a9a00, без замены похожим оттенком

### Requirement: Results are verified and remain in chat
Система SHALL проверять сохранённое значение и обновление оформления перед подтверждением полного успеха. Ответ о стандартной настройке SHALL оставаться в чате без открытия карточки приёма.

#### Scenario: Successful change
- **WHEN** значение сохранено и предусмотренная проверка обновления успешно завершена
- **THEN** ответ сообщает фактический результат и текущая страница остаётся открытой

#### Scenario: Partial success
- **WHEN** значение сохранено, но обновление оформления не подтверждено
- **THEN** ответ явно различает сохранение и неподтверждённый визуальный результат, не утверждая полного успеха

### Requirement: Previous values and existing behavior are preserved
Система SHALL сохранять предыдущее значение для восстановления конкретного изменения и защищать более поздние внешние правки. Система SHALL сохранять действующие пути приёмов и параметров и учёт расходов, включая ошибки API.

#### Scenario: Restore an unchanged result
- **WHEN** пользователь просит восстановить предыдущее значение и настройка после действия не менялась
- **THEN** система восстанавливает сохранённое предыдущее значение через проверенный исполнитель

#### Scenario: Manual change after chat action
- **WHEN** настройка изменена вручную после действия чата и запрошено восстановление
- **THEN** система не затирает новое значение молча и объясняет конфликт
