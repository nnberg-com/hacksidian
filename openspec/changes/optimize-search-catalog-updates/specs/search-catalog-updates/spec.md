## ADDED Requirements

### Requirement: Incremental updates preserve catalog coverage
Система SHALL синхронизировать полный набор допустимых поисковых записей, определяя добавления, изменения и удаления по стабильному ID и хешу сформированного поискового документа. Неизменённые документы MUST NOT повторно загружаться или индексироваться при обычном обновлении существующего совместимого индекса.

#### Scenario: One document changes
- **GIVEN** существует готовый совместимый индекс и изменился поисковый документ одного приёма
- **WHEN** пользователь обновляет каталог
- **THEN** загружается и индексируется новая версия только этого документа
- **AND** неизменённые документы остаются доступными без повторной индексации
- **AND** устаревшая версия изменённого документа перестаёт участвовать в поиске после успешного завершения

#### Scenario: Additions and removals
- **GIVEN** добавлены две записи и удалена одна запись
- **WHEN** обновление завершается успешно
- **THEN** индексируются только два новых документа, удалённая запись больше не выдаётся
- **AND** остальные записи не переиндексируются

### Requirement: No-op updates avoid remote mutations
Система SHALL определять отсутствие изменений по поисковым документам. При доступном готовом индексе без изменений система MUST NOT создавать Vector Store, загружать Files или запускать индексацию. Проверка состояния удалённого индекса допустима.

#### Scenario: Repeated update
- **GIVEN** предыдущая синхронизация завершена и содержимое поисковых документов не изменилось
- **WHEN** пользователь повторяет обновление
- **THEN** удалённые ресурсы каталога не изменяются
- **AND** интерфейс сообщает об отсутствии изменений

#### Scenario: Non-search source changes
- **GIVEN** изменился исходный файл, но сформированные поисковые документы остались прежними
- **WHEN** пользователь обновляет каталог
- **THEN** документы не загружаются и не индексируются повторно

### Requirement: Updates remain recoverable and consistent
Система SHALL сохранять журнал незавершённой синхронизации и идентификаторы созданных ресурсов. Система MUST NOT объявлять незавершённое обновление успешным. После прерывания система SHALL разрешать поиск по действующему снимку и сохранённым файлам журнала загрузки того же индекса, сопоставляя источники с известными ID карточек. Файлы другого индекса и незарегистрированные источники MUST NOT подтверждать рекомендацию.

#### Scenario: Failure after partial remote changes
- **GIVEN** часть удалённых операций выполнена, а следующая завершилась ошибкой
- **WHEN** синхронизация прерывается
- **THEN** интерфейс сообщает об ошибке и незавершённом состоянии
- **AND** журнал позволяет повторить или восстановить операцию без бесконтрольного дублирования ресурсов
- **AND** частично изменённый индекс не выдаётся за готовую версию

#### Scenario: Restart during synchronization
- **GIVEN** приложение завершилось во время обновления
- **WHEN** плагин запускается снова
- **THEN** он распознаёт незавершённую операцию и не теряет сведения о её ресурсах
- **AND** согласованное состояние восстанавливается до возобновления поиска по обновлённой версии

### Requirement: Full rebuilds have explicit reasons
Система SHALL допускать полную индексацию при отсутствии рабочего индекса, его истечении или подтверждённой утрате, несовместимом изменении формата либо явном запросе пользователя на восстановление. Обычная правка записи MUST NOT быть причиной полной переиндексации. Временная ошибка сети или авторизации сама по себе MUST NOT трактоваться как утрата индекса.

#### Scenario: Initial catalog
- **GIVEN** рабочего индекса нет
- **WHEN** пользователь запускает индексацию
- **THEN** создаётся полный индекс допустимых записей с сообщением о первичной индексации

#### Scenario: Expired index
- **GIVEN** подтверждено, что прежний индекс истёк или удалён
- **WHEN** пользователь обновляет каталог
- **THEN** система объясняет причину полной индексации и восстанавливает полный каталог

### Requirement: Progress reflects actual synchronization work
Система SHALL показывать количество новых, изменённых, удалённых и неизменённых документов. Прогресс загрузки и индексации SHALL относиться к фактически обрабатываемому набору, а не создавать впечатление повторной загрузки всего атласа.

#### Scenario: Small update in a large catalog
- **GIVEN** из 1500 поисковых документов изменился один
- **WHEN** начинается обычное обновление
- **THEN** интерфейс показывает один изменённый документ и 1499 неизменённых
- **AND** прогресс индексации относится к одному изменённому документу


### Requirement: Indexing has observable phases and bounded waiting
Система SHALL различать локальную подготовку, загрузку файлов, серверную индексацию и очистку ресурсов. При ожидании сервера система SHALL показывать доступные счётчики обработанных, ожидающих и ошибочных документов, прошедшее время и последнюю успешную проверку состояния. Каждый сетевой запрос и вся операция SHALL иметь конечные сроки, не зависящие от возвращения зависшего запроса.

#### Scenario: Server continues indexing
- **WHEN** API отвечает состоянием in_progress
- **THEN** интерфейс показывает серверную индексацию и обновляет счётчики и время последней проверки
- **AND** это состояние отличается от загрузки файлов и отсутствия ответа сервера

#### Scenario: Status request never returns
- **WHEN** запрос состояния не отвечает до своего срока
- **THEN** ожидание запроса завершается локально, интерфейс сообщает о проблеме связи
- **AND** ограниченные повторы не обходят общий срок операции
- **AND** журнал сохраняется, поздний ответ не завершает отменённую или заменённую операцию

### Requirement: Cancellation preserves recovery information
Система SHALL позволять пользователю отменить обновление. Отмена SHALL останавливать запуск новых действий и сохранять данные восстановления. Система MUST NOT утверждать, что уже отправленные серверные операции отменены, без подтверждения сервера.

#### Scenario: Cancel during indexing
- **WHEN** пользователь отменяет ожидание индексации
- **THEN** плагин прекращает новые действия и показывает отмену локальной операции
- **AND** сохраняет идентификаторы ресурсов и сведения о неизвестном результате удалённых операций
- **AND** поиск возобновляется только на согласованной версии

### Requirement: Stale document versions cannot inform answers
Система SHALL учитывать задержку исключения удалённых документов из результатов поиска. После переключения каталога устаревшие версии файлов MUST NOT использоваться при формировании ответа, даже если ID приёма сохранился.

#### Scenario: Search returns an obsolete file version
- **GIVEN** приём получил новый fileId, а поиск ещё возвращает фрагмент старого fileId
- **WHEN** формируется ответ после переключения каталога
- **THEN** старый фрагмент исключается до передачи контекста модели либо ответ приостанавливается до обеспечения согласованности

### Requirement: Cost explanations distinguish storage and model usage
Система SHALL объяснять различие между хранением индекса, вызовами File Search и входными/выходными токенами модели. Индексация через управляемый Vector Store MUST NOT отображаться как отдельный расход токенов чат-модели. Неизвестная стоимость хранения MUST NOT отображаться как подтверждённый ноль.

#### Scenario: User indexes without asking a question
- **WHEN** выполняется только загрузка и индексация документов без генерации ответа
- **THEN** интерфейс не приписывает этой операции токены или вызовы поиска, которых не было
- **AND** объясняет отдельную оплату хранения без обещания доступной бесплатной квоты

### Requirement: Пользователь может остановить обновление
Интерфейс SHALL показывать «Обработано N из M файлов» и кнопку «Остановить» рядом со статусом обновления в панели чата и настройках. Остановка SHALL сохранять журнал и прекращать новые сетевые запросы после завершения текущего запроса. Интерфейс SHALL освободить блокировку операций после остановки.

#### Scenario: Остановка во время загрузки
- **WHEN** пользователь нажимает «Остановить» при выполняющемся запросе загрузки
- **THEN** возвращённый идентификатор файла сохраняется перед остановкой
- **AND** следующее обновление повторно использует этот файл
