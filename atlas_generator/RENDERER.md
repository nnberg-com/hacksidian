# Контракт рендеринга, версия 1

Контракт хранится в коде render.py и тестах tests/test_generator.py.
Этот документ объясняет правила; промпт для каждой сборки не нужен.
Версии парсера и расширений закреплены в requirements.txt.

## Markdown и HTML

Основа — CommonMark, дополненный таблицами, зачёркиванием, сносками и списками определений.
HTML внутри примера сохраняется. Скрипты и обработчики событий из примера удаляются.
Пользовательский JavaScript в примерах не исполняется; штатные details, ссылки, формы и CSS остаются.

Корень примера: .atlas-<ID>.markdown-preview-view.markdown-rendered.
snippet.css подключается после общей базовой стилизации.
Заголовки получают data-heading и ID с префиксом source_anchor (если есть), иначе ID приёма.
Повторяющиеся заголовки получают числовой суффикс.
Сноски используют тот же префикс, сохраняют отдельные обратные ссылки при повторных упоминаниях.
Таблицы получают и style text-align, и align для совместимости селекторов.

Поддерживаются ==выделение==, #теги, wikilinks и embeds.
Встроенный код и fenced code не интерпретируются как теги или выделение.
Wikilinks демонстрируют разметку, но не разрешают произвольные заметки всего vault.

Маркеры задач сохраняются в data-task; обычный checkbox доступен для переключения.
При переключении обновляются data-task и is-checked.

Callout преобразуется в .callout с data-callout, заголовком, иконкой и .callout-content.
Форматированный заголовок сохраняется. Вложенные блоки обрабатываются изнутри наружу.
Складные callout используют details/summary, начальное раскрытие определяется знаком + или -.
Для семейства callout-technical-gh используется структура markdown-alert.

Отсутствующим целям внутренних ссылок создаются демонстрационные назначения за пределами
корня примера, чтобы не менять nth-child и другие структурные селекторы.

## Properties и сохранённые модели

YAML из Markdown.<lang>.md — источник значений Properties.
Сохранённая Model.<lang>.html предоставляет структуру панели: строки обновляются,
добавляются и удаляются по текущему YAML. Текст примера также строится заново.
При отсутствии модели используется базовая структура Properties.

Из Model.css берётся оформление окружения; старые правила конкретного приёма и keyframes
удаляются, после чего подключается актуальный snippet.css.
Исходная модель отдельно доступна как справочный пример и не заменяет актуальный Markdown
в обычных markdown/html-приёмах.

CodeMirror в сохранённых моделях — статическая имитация DOM.
Этот контракт не обещает идентичность всем версиям Obsidian, темам и плагинам.

## Оболочка

preview.css задаёт общие шрифты, размеры, базовые элементы Markdown и переменные окружения.
Окружение отличается от индивидуального snippet.css: оно принадлежит генератору.
Каждая демонстрация находится в отдельном iframe.
preview.js обслуживает только состояние задач и складных блоков.
Сценарии автоматической записи GIF не входят в генератор.

## CSS-шаблоны и режим Obsidian

CSS приёма читается из одного recipe.css без преобразований. В режиме --obsidian-config базовое окружение задают настоящий app.css, тема и включённые сниппеты. В автономном режиме его задаёт общий static/preview.css. CSS не создаёт недостающую структуру редактора. Исходная картотека при сборке не изменяется.
