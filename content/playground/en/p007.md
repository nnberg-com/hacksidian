# Code within a long technical text

## This sample helps tune the reading experience of an article in which ordinary prose repeatedly gives way to code in several languages.

A good code block should stand apart from a paragraph without falling out of the article's rhythm. Readers should easily find the beginning and end of an example, distinguish comments, strings, numbers, and keywords, then return comfortably to ordinary text. Below, a small task appears in five languages so the styling can be assessed against a real set of constructs.

### C: data, pointers, and explicit boundaries

C makes preprocessor directives, types, numeric constants, pointers, and standard library functions particularly visible. This example accumulates sensor values and prints their average. It includes a multiline signature, an early return, a format string, and a comment: a varied set of elements for checking contrast.

```c
#include <stdio.h>
#include <stddef.h>

#define SAMPLE_LIMIT 8

typedef struct {
    const char *name;
    double values[SAMPLE_LIMIT];
    size_t count;
} SensorSeries;

static double average(const SensorSeries *series) {
    if (series == NULL || series->count == 0) {
        return 0.0;
    }

    double total = 0.0;
    for (size_t i = 0; i < series->count; ++i) {
        total += series->values[i];
    }
    return total / (double)series->count;
}

int main(void) {
    SensorSeries room = {
        .name = "studio",
        .values = {21.4, 21.8, 22.1, 21.9},
        .count = 4,
    };

    /* Keep the unit next to the value in human-readable output. */
    printf("%s: %.1f °C\n", room.name, average(&room));
    return 0;
}
```

After a dense block, check the return to a proportional font. If the background is too heavy, code takes over the page; if the boundary is barely visible, the example merges with adjacent paragraphs. The expression `average(&room)` deserves particular attention: inline code should be related to the larger block without turning a line of text into a sequence of badges.

### Bash: commands, variables, and output streams

A shell script creates a different pattern. It contains many special characters, quotes, substitutions, short commands, and long arguments. Highlighting should reveal the structure without making `$`, `{}`, and `[]` brighter than the meaningful parts.

```bash
#!/usr/bin/env bash
set -euo pipefail

readonly SOURCE_DIR="${1:-./samples}"
readonly REPORT_FILE="${2:-./build/report.tsv}"

collect_reports() {
  local file
  mkdir -p "$(dirname "$REPORT_FILE")"
  : > "$REPORT_FILE"

  while IFS= read -r -d '' file; do
    printf '%s\t%s\n' \
      "$(basename "$file")" \
      "$(wc -l < "$file" | tr -d ' ')" \
      >> "$REPORT_FILE"
  done < <(find "$SOURCE_DIR" -type f -name '*.log' -print0)
}

if [[ ! -d "$SOURCE_DIR" ]]; then
  printf 'Directory not found: %s\n' "$SOURCE_DIR" >&2
  exit 1
fi

collect_reports
printf 'Saved %s\n' "$REPORT_FILE"
```

In the Bash block, examine the continuation of the long command and whether quotes disappear beside variables. A technical article surrounding this kind of example often includes short commands such as `chmod +x report.sh` and filenames such as `report.tsv`, so their appearance within a line is also part of the composition.

### Python: types, strings, and expressions

Python provides more space through indentation, but long type annotations and formatted strings soon restore visual density. The example includes a decorator, `None`, a generator expression, an exception, and an f-string. A comment deliberately appears between working lines rather than in a separate header.

```python
from dataclasses import dataclass
from statistics import fmean
from typing import Iterable


@dataclass(frozen=True, slots=True)
class Reading:
    sensor: str
    value: float
    unit: str = "°C"


def summarize(readings: Iterable[Reading]) -> dict[str, float]:
    grouped: dict[str, list[float]] = {}
    for reading in readings:
        grouped.setdefault(reading.sensor, []).append(reading.value)

    if not grouped:
        raise ValueError("at least one reading is required")

    # Round only the value shown to a person; preserve source precision.
    return {
        sensor: round(fmean(values), 1)
        for sensor, values in grouped.items()
    }


summary = summarize([
    Reading("studio", 21.4),
    Reading("studio", 21.8),
    Reading("kitchen", 23.05),
])
print(f"Studio average: {summary['studio']:.1f} °C")
```

If comments become almost invisible, explanatory code is hard to read; if they are too prominent, they compete with executable lines. Strings and numbers should also differ without resembling festive lights. This is especially apparent beside an ordinary paragraph containing *italics*, **strong emphasis**, and a link to the [syntax documentation](https://help.obsidian.md/syntax).

### JavaScript: objects and asynchronous work

JavaScript helps test arrow functions, template strings, optional chaining, and `async`/`await`. The code below receives an existing JSON response, discards invalid records, and produces labels suitable for an interface. It is a typical application fragment rather than an artificial list of tokens.

```javascript
const endpoint = new URL("/api/readings", window.location.origin);
endpoint.searchParams.set("room", "studio");

async function loadReadings(signal) {
  const response = await fetch(endpoint, {
    headers: { Accept: "application/json" },
    signal,
  });

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  const payload = await response.json();
  return payload.items
    .filter((item) => Number.isFinite(item?.value))
    .map(({ sensor, value, unit = "°C" }) => ({
      id: crypto.randomUUID(),
      label: `${sensor}: ${value.toFixed(1)} ${unit}`,
    }));
}

const controller = new AbortController();
loadReadings(controller.signal)
  .then((items) => console.table(items))
  .catch((error) => console.error("Could not load readings", error));
```

This block contains particularly dense punctuation. Brackets and commas need not be accents, but they must remain distinguishable against the chosen background. Check horizontal behaviour too: the error-handler line is fairly long, but not so long that it should determine the width of the entire article.

### TypeScript: types as a second voice

TypeScript adds a layer absent from JavaScript: types are read alongside the program but serve a different purpose. Highlighting them too faintly loses the meaning of the example; making them too bright pushes the main logic into the background. This example uses literal unions, an interface, a generic type, variant checks, and the `satisfies` operator.

```typescript
type Unit = "°C" | "%";

interface Reading<TUnit extends Unit = Unit> {
  sensor: string;
  value: number;
  unit: TUnit;
  capturedAt: Date;
}

type LoadState<T> =
  | { status: "idle" }
  | { status: "loading"; startedAt: number }
  | { status: "ready"; data: readonly T[] }
  | { status: "failed"; error: Error };

function describeState<T>(state: LoadState<T>): string {
  switch (state.status) {
    case "idle":
      return "No request yet";
    case "loading":
      return `Loading for ${Date.now() - state.startedAt} ms`;
    case "ready":
      return `${state.data.length} readings available`;
    case "failed":
      return state.error.message;
  }
}

const current = {
  status: "ready",
  data: [{
    sensor: "studio",
    value: 21.8,
    unit: "°C",
    capturedAt: new Date("2026-09-03T12:00:00Z"),
  }],
} satisfies LoadState<Reading<"°C">>;

console.info(describeState(current));
```

After five examples, you can assess the system as a whole. Is the language name visible enough when the interface shows it? Does the block need a border? Should its corners be square or rounded? Is selecting code with a mouse comfortable? Does the space before an example look arbitrarily larger than the space after it?

### Returning to ordinary reading

A technical article remains an article even when it contains a lot of code. The final passage consists of ordinary sentences again, allowing you to feel calm after the coloured tokens or, conversely, notice a lack of visual connection. Code blocks are large objects within the text rather than a separate gallery of samples.

The sample works well when the eye moves easily between explanation and implementation: the heading sets the subject, the paragraph establishes expectations, the block reveals details, and the next sentence resumes the argument. Every example can be edited as an ordinary Markdown document; CallMeRed should work with what the user actually leaves on the page.
