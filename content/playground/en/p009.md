# Callouts in a long article

## A callout should change the level of attention within an article without turning the surrounding text into captions for a collection of coloured blocks.

This page brings together the built-in callout types and their official aliases. They are distributed across sections of continuous text so you can assess both the blocks themselves and the return to ordinary reading.

### Neutral and reference callouts

The first section starts with an ordinary paragraph. Neutral callouts usually accompany an explanation, so they should fit quietly into its rhythm.

> [!NOTE] NOTE — primary type
> A neutral note without additional connotations.

> [!ABSTRACT] ABSTRACT — primary type
> A brief summary or overview of the content.

> [!SUMMARY] SUMMARY — alias of ABSTRACT
> The same visual type, invoked with the `summary` identifier.

> [!TLDR] TLDR — alias of ABSTRACT
> The same visual type, invoked with the `tldr` identifier.

> [!INFO] INFO — primary type
> Reference information alongside the main text.

> [!TODO] TODO — primary type
> An action or task that remains to be completed.

After the neutral callouts, the article returns to prose. This paragraph reveals the lower spacing and helps identify an overly heavy band of colour.

### Tips and successful states

A tip follows a problem statement, while a success message follows an action. Ordinary textual context connects them.

> [!TIP] TIP — primary type
> Practical advice or a useful technique.

> [!HINT] HINT — alias of TIP
> The same visual type, invoked with the `hint` identifier.

> [!IMPORTANT] IMPORTANT — alias of TIP
> The same visual type, invoked with the `important` identifier.

> [!SUCCESS] SUCCESS — primary type
> A positive result or a successfully completed action.

> [!CHECK] CHECK — alias of SUCCESS
> The same visual type, invoked with the `check` identifier.

> [!DONE] DONE — alias of SUCCESS
> The same visual type, invoked with the `done` identifier.

An ordinary paragraph after positive states should not appear faint simply because coloured accents came before it.

### Questions and warnings

In a long article, a question or warning interrupts the argument more strongly, so padding, the icon, and heading contrast matter especially here.

> [!QUESTION] QUESTION — primary type
> A question requiring an answer or further investigation.

> [!HELP] HELP — alias of QUESTION
> The same visual type, invoked with the `help` identifier.

> [!FAQ] FAQ — alias of QUESTION
> The same visual type, invoked with the `faq` identifier.

> [!WARNING] WARNING — primary type
> A warning about a possible problem.

> [!CAUTION] CAUTION — alias of WARNING
> The same visual type, invoked with the `caution` identifier.

> [!ATTENTION] ATTENTION — alias of WARNING
> The same visual type, invoked with the `attention` identifier.

After the warnings, reading continues with a quiet sentence. It tests how easily the eye leaves a prominent block.

### Errors and dangerous states

Critical states should differ as much as the content requires without disrupting the typography of the entire page.

> [!FAILURE] FAILURE — primary type
> An unsuccessful result or an incomplete action.

> [!FAIL] FAIL — alias of FAILURE
> The same visual type, invoked with the `fail` identifier.

> [!MISSING] MISSING — alias of FAILURE
> The same visual type, invoked with the `missing` identifier.

> [!DANGER] DANGER — primary type
> A dangerous action or a critical condition.

> [!ERROR] ERROR — alias of DANGER
> The same visual type, invoked with the `error` identifier.

> [!BUG] BUG — primary type
> An error or observed incorrect behaviour.

The next paragraph again occupies the ordinary text column, restoring the article's main voice.

### Examples and quotes

An example or quote may be longer than a typical status message. It should support reading several lines in succession.

> [!EXAMPLE] EXAMPLE — primary type
> A standalone example separated from its explanation.

> [!QUOTE] QUOTE — primary type
> A quotation presented as a callout.

> [!CITE] CITE — alias of QUOTE
> The same visual type, invoked with the `cite` identifier.

Here an ordinary paragraph separates semantic types from variations in the behaviour of the same component.

### Behaviour variations

The final section tests collapsing, missing body content, and nesting. These are uncommon but visually significant states within an article.

> [!INFO]+ INFO — expanded collapsible callout
> The `+` sign leaves the contents open but allows them to be collapsed.

> [!QUESTION]- QUESTION — collapsed callout
> The `-` sign initially hides this block's contents.

> [!TIP] TIP — title-only callout

> [!QUESTION] QUESTION — first nesting level
> The outer callout contains the next block.
> > [!TODO] TODO — second nesting level
> > Another variation appears inside it.
> > > [!EXAMPLE] EXAMPLE — third nesting level
> > > This reveals the indentation and borders of several levels.

The final paragraph concludes the article with ordinary text. If the system works, even a large collection of callouts remains part of the reading experience rather than a standalone component showcase.
