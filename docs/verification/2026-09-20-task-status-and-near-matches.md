# Статус task-e65 и видимые неполные совпадения

## task-e65

Рецепт предполагал соседство `h2 + ul`; подпись «в работе» при этом добавлялась всем H2 безусловно. В Reading View с отдельными `.el-h2` / `.el-ul` такое условие завершённости не выполняется. Добавлены обе структуры, нумерованные списки и отсутствие подписи без соседнего списка задач. Вложенные неотмеченные флажки оставляют статус незавершённым.

Добавлен независимый текстовый параметр «Подпись раздела в работе» / In-progress section label, `--hacksidian-task-e65-progress-label`, значение по умолчанию «в работе», до 40 символов, пустая строка допустима. Существующее значение завершённого раздела `done` сохранено.

Изолированная браузерная проверка: 9 вариантов, переключение флажков, произвольная и пустая подпись — PASS. Проверено через локальную страницу в браузере Codex; самостоятельный headless Chromium не запустился в доступной среде. В самом Obsidian результат не осмотрен. Скрипт повторяемой проверки: `plugin/scripts/verify-task-e65.mjs` (требует Playwright и Chromium).

## Неполные совпадения

Ответ модели получил поле `alternatives`: до шести проверенных ID с объяснением эффекта и несоответствия запросу. Промпт требует включать туда обсуждаемые близкие/сомнительные варианты, в том числе при `no_match` и `ask_question`, вместо безымянных упоминаний в тексте.

Приложение проверяет ID и показывает тот же ChatTechnique: название-ссылку, избранное, кнопку включения и живой пример. Отдельная подпись обозначает неполное соответствие. Альтернативы проходят вне пути преднастройки и автоматического применения. Произвольные команды в них отвергаются; неизвестные и повторные ID также отвергаются.

Это изменение представления и контракта ответа. Оно не является доказательством, что в каталоге отсутствует приём двух колонок для обычных списков. Старые текстовые ответы без записанных ID автоматически не восстанавливаются.
