# Выпуск шаблонного vault

Эталон — рабочий vault, где автор настраивает Obsidian. `content/atlas` и `content/playground` уже находятся в Git; ссылки из эталона нужны только для удобной работы. Экспорт не копирует эти материалы повторно.

## Порядок выпуска

Сначала экспорт, затем коммит и push: скрипт обновляет файлы проекта, которые должны попасть в релиз.

1. Закончите настройку эталонного vault и правки его `INSTALL.md`, затем закройте Obsidian.
2. Из корня проекта запустите экспорт:

   ```sh
   python3 tools/vault-release.py export /Users/op/vaults/hacksidian --apply
   ```

3. Проверьте изменения, закоммитьте и отправьте их в GitHub. В коммит должны попасть обновлённые `vault-template/`, `vault-dependencies.json` и остальные подготовленные изменения проекта.
4. Для выпуска создайте тег на нужном коммите и отправьте его:

   ```sh
   git tag vault-0.1.0
   git push origin vault-0.1.0
   ```

   `vault-0.1.0` — пример: для каждого нового выпуска используйте новый номер версии.

5. Дождитесь завершения workflow `Build vault release`. Скачайте ZIP из черновика GitHub Release, распакуйте и проверьте его в Obsidian. Затем опубликуйте релиз.

Если экспорт уже выполнен и после него настройки, сниппеты, плагины и `INSTALL.md` эталона не менялись, повторять экспорт перед коммитом не нужно.

## После настройки эталона

Закройте Obsidian, чтобы настройки не менялись во время экспорта. Отредактируйте `INSTALL.md` в корне эталона при необходимости.

Предпросмотр (ничего не записывает, скачивает зависимости для проверки):

```sh
python3 tools/vault-release.py export /Users/op/vaults/hacksidian
```

Применение:

```sh
python3 tools/vault-release.py export /Users/op/vaults/hacksidian --apply
```

Путь может быть любым. В Git идут `vault-template/` и `vault-dependencies.json`. Проверьте diff и зафиксируйте их вместе с изменениями контента и кода.

Экспорт полностью заменяет только `vault-template/`: удалённые сниппеты и настройки отключённых плагинов не остаются в старой копии. Редактировать экспорт вручную не следует; следующий экспорт заменит его.

Явный список файлов настроек находится в `CONFIGS` скрипта. Переносятся эти JSON, CSS-сниппеты, очищенные `data.json` включённых плагинов и `INSTALL.md`. Workspace, кэши и прочие файлы не экспортируются. В Hacksidian сохраняются только настройки и локализация; история, расходы, каталог и отметка установки исключаются. Распознанные секреты очищаются до записи в проект. Очистка по названиям полей не заменяет просмотра diff при добавлении новых настроек сторонних плагинов.

Код сторонних плагинов, лицензии и наборы иконок в Git не сохраняются. Экспорт закрепляет установленные версии и SHA-256 файлов официальных релизов; сборка скачивает их и проверяет суммы. Если установленная версия не имеет доступного релиза, экспорт завершится ошибкой. Новые неизвестные наборы иконок и сторонние темы требуют добавления источников скачивания. Сейчас поддерживаются используемые наборы Font Awesome 6.5.1, включая лицензию внутри ZIP.

## Локальная сборка

```sh
npm --prefix plugin ci
npm --prefix plugin run release:prepare
python3 tools/vault-release.py build build/vault/Hacksidian-preview.zip
```

Сборка берёт контент и пресет из проекта, скачивает зависимости и добавляет свежую сборку Hacksidian. Нужен доступ к сети. Эталон и абсолютные пути автора не требуются. Существующий ZIP не перезаписывается.

Рядом с ZIP создаются SHA-256 и отчёт с составом, версиями и хешами. Внутри — одна папка, которую можно переименовать. Папка `_templates` не создаётся.

## GitHub Release

Workflow `Build vault release` проверяет сборку в pull request и по ручному запуску. Теги вида `vault-0.1.0` собирают комплект и создают **черновик** GitHub Release с ZIP, отчётом и SHA-256. После проверки распакованного архива опубликуйте черновик в GitHub. Версия комплекта независима от версии плагина; теги релиза плагина по-прежнему совпадают с `plugin/manifest.json` без префикса `v`.

Автоматический `Source code.zip` на GitHub — исходники, а не готовое хранилище.

Перед публикацией откройте распакованный комплект под другим именем в настольном Obsidian, разрешите плагины и проверьте атлас, песочницу, оформление и навигацию. Сборка и тесты не заменяют эту проверку. Обновление существующих пользовательских vault пока не входит в процесс.

## Проверки

```sh
python3 -m unittest discover -s tools/tests -p 'test_*vault*.py' -v
```

`tools/build-starter-vault.py` также остаётся доступен для разовой упаковки готового vault; основной релиз собирается через `vault-release.py` из Git.
