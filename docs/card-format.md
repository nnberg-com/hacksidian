# Карточка приёма

Markdown-карточка редактируется непосредственно. Автоматическая перезапись карточек генераторами и форматтерами отключена.

В папке приёма остаются содержательные файлы: `<код>.md`, `recipe.css`, `markdown.md` (если пример существует) и необходимые ресурсы примера. Конфигурация применения `hack.json` также хранится в папке самого приёма: она непосредственно относится к нему и публикуется вместе с рецептом.

`hack.json` содержит формат конфигурации, целевой сниппет, наличие CSS, техническую группу и требования. Он необходим для применения рецепта. Файлы `baseline.json`, `provenance.json` и справочный `default.css` удалены: работа плагина от них не зависит. Исторические отчёты не создаются заново при редактировании карточек.

В свойствах сначала идут `tags`, затем `title`. Теги используют префикс `hacksidian_`. В `themes` перечисляются коды тем — имена страниц в `! themes`, без путей и расширений. Исходные ссылки остаются в `sources` и разделе «Источники». Объяснения оформлены пунктами «Зачем», «Как работает», «Ограничения».

Блоки `hacksidian-id`, `hacksidian-live` и `hacksidian-files` принимают код приёма. Первый показывает копируемый код, второй — живой пример с переключателем, третий — CSS и Markdown в соседних колонках со штатной подсветкой Obsidian и ссылками для редактирования.

`hacksidian-sources` принимает только код приёма. В колонке «Темы» выводятся ссылки из свойства `themes`, в колонке «Детали» — ссылки из свойства `sources`. Внешние ссылки подписаны доменами. Метаданные карточки — единственный источник списка ссылок; изменения `sources` обновляют блок. Отдельные пояснения о происхождении остаются обычным Markdown рядом с блоком. Устаревшие ссылки на исходный HTML-атлас удалены; безымянные внешние источники подписаны доменами.

Совместимость с отдельными блоками `hacksidian-css` и `hacksidian-markdown` сохранена. Исходники выводятся буквально, вложенные блоки не исполняются. Изменения файлов обновляют код. Пустые и отсутствующие примеры обозначаются явно.

CSS открывается через [URL-протокол VSCode](https://code.visualstudio.com/docs/configure/command-line#_opening-vs-code-with-urls), Markdown — в режиме редактирования Obsidian. Локальные зависимости лежат в `assets/`.

Для форматирования CSS без изменения разобранных правил: `node tools/format-recipe-css.mjs /path/to/atlas`. Prettier используется с проверкой дерева PostCSS; при изменении дерева применяется только форматирование пробелов и переносов.

Проверка структуры без генерации:

```sh
node tools/verify-card-format.mjs /path/to/atlas
node tools/verify-recipe-catalog.mjs
```

## Избранное

Рядом с кодом приёма отображается звёздочка: нажатие добавляет карточку в избранное или убирает её. Кнопка «Избранное», значок звезды в боковой панели и команда Hacksidian «Открыть избранное» открывают страницу `atlas/Избранное.md`. На ней блок `hacksidian-favourites` показывает актуальный список с поиском и возможностью снять отметку. Поиск работает по названию и коду; карточки упорядочены по пути.

Отметка хранится непосредственно в YAML карточки: `favourite: true`. Повторное нажатие записывает `favourite: false`. Список строится из метаданных карточек; отдельного хранилища избранного нет. Ручное изменение свойства обновляет звёздочку и список. Старые отметки из данных плагина переносятся в карточки при первом запуске новой версии.

## Верхний ряд и пояснения

`hacksidian-id` показывает код, жирный `title`, избранное и кнопку включения/выключения CSS. Кнопка применяется к карточке этого блока, независимо от фокуса панели диалога. В диалоге отдельные название и кнопка применения больше не выводятся.

В блоке `hacksidian-details` каждая строка `> Название` начинает новую колонку. Следующий Markdown до следующего такого заголовка — содержимое колонки. Пример:

````markdown
```hacksidian-details
> Зачем
Описание пользы.

> Как работает
Описание механизма.

> Ограничения
Условия применения.
```
````

При узкой панели колонки переносятся. Внешние заголовки «Источники» и разделы «Демонстрация» удалены из карточек.

All card headings use level six, including Details, Sources and Files component headings. Demonstration Markdown retains its own heading levels because those levels are part of the technique sample. The CSS editor action is a `VSCode` button; the `Markdown` heading links directly to the source note in edit mode. General historical section boilerplate has been removed: useful conditions are in the corresponding details column, provenance is in source details.

## Граница каталога

В `! hacks` находятся только самостоятельные CSS-сниппеты: `hack.json` с `hasCss: true` и непустой `recipe.css`. Настройки тем и исследовательские находки без рецепта не являются карточками приёмов. Сборщик поискового каталога исключает такие записи; проверка карточек запрещает их возвращение. Картотека тем остаётся контекстом происхождения сниппетов.

Верх карточки: ссылки на категорию и избранное; ниже — название, код, крупная звезда и справа переключатель примера с кнопкой применения после него. Код — штатный inline `code`, без копии его CSS. Кнопка включения и звезда используют `--color-green`, кнопка выключения — `--color-red`.

Страница `Включённые.md` содержит блок `hacksidian-enabled`: он читает текущие применённые блоки CSS из файлов сниппетов, показывает ссылки на карточки и поиск по названию/коду. Список обновляется при включении, выключении и внешнем изменении CSS. Ссылка «Включённые» находится рядом с «Избранное» в верхней навигации карточки.

Страницы категорий используют `hacksidian-category` с кодом категории. Блок автоматически собирает карточки по `category`, показывает их общий заголовок и кнопки без верхней навигации, затем живой пример или причину его отсутствия. Название ведёт к карточке. Примеры подгружаются по мере прокрутки. Исходники и базовые переменные отдельными разделами категорий больше не публикуются.
