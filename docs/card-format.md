# Карточка приёма

Markdown-карточка редактируется непосредственно. Автоматическая перезапись карточек генераторами и форматтерами отключена.

В папке приёма остаются содержательные файлы: `<код>.md`, `recipe.css`, `markdown.md` (если пример существует) и необходимые ресурсы примера. Конфигурация применения `hack.json` также хранится в папке самого приёма: она непосредственно относится к нему и публикуется вместе с рецептом.

`hack.json` содержит формат конфигурации, целевой сниппет, наличие CSS, техническую группу и требования. Он необходим для применения рецепта. Файлы `baseline.json`, `provenance.json` и справочный `default.css` удалены: работа плагина от них не зависит. Исторические отчёты не создаются заново при редактировании карточек.

В свойствах сначала идут `tags`, затем `title`. Теги используют префикс `hacksidian_`. В `themes` перечисляются коды тем — имена страниц в `! themes`, без путей и расширений. Исходные ссылки остаются в `sources` и разделе «Источники». Объяснения оформлены пунктами «Зачем», «Как работает», «Ограничения».

Блоки `hacksidian-id`, `hacksidian-live` и `hacksidian-files` принимают код приёма. Первый показывает копируемый код, второй — живой пример с переключателем, третий — CSS и Markdown в соседних колонках со штатной подсветкой Obsidian и ссылками для редактирования.

`hacksidian-sources` принимает код первой строкой и Markdown подробностей на следующих строках. В колонке «Темы» выводятся ссылки из свойства `themes`, в колонке «Подробности» — этот Markdown. Подробности остаются редактируемой частью карточки. Устаревшие ссылки на исходный HTML-атлас удалены; безымянные внешние источники подписаны доменами.

Совместимость с отдельными блоками `hacksidian-css` и `hacksidian-markdown` сохранена. Исходники выводятся буквально, вложенные блоки не исполняются. Изменения файлов обновляют код. Пустые и отсутствующие примеры обозначаются явно.

CSS открывается через [URL-протокол VSCode](https://code.visualstudio.com/docs/configure/command-line#_opening-vs-code-with-urls), Markdown — в режиме редактирования Obsidian. Локальные зависимости лежат в `assets/`.

Для форматирования CSS без изменения разобранных правил: `node tools/format-recipe-css.mjs /path/to/atlas`. Prettier используется с проверкой дерева PostCSS; при изменении дерева применяется только форматирование пробелов и переносов.

Проверка структуры без генерации:

```sh
node tools/verify-card-format.mjs /path/to/atlas
node tools/verify-recipe-catalog.mjs
```
