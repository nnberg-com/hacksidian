# Локальная установка: плагин и две символические ссылки

На этом этапе поддерживается только локальная авторская установка из рабочей копии репозитория. Материалы не упаковываются, не скачиваются и не копируются в vault.

## Установка

Закрыть Obsidian. Выбрать отдельный существующий vault вне репозитория. Из корня репозитория выполнить:

```sh
npm --prefix plugin ci
HACKSIDIAN_VAULT="/absolute/path/to/vault" npm --prefix plugin run install:vault
```

Путь к vault обязателен. `HACKSIDIAN_CONFIG_DIR` при необходимости задаёт папку конфигурации вместо `.obsidian`.

Установщик копирует файлы плагина (`main.js`, `manifest.json`, `styles.css`), сохраняет настройки и историю существующей установки и включает плагин. Для материалов создаёт ровно две ссылки:

```text
vault/Hacksidian/atlas      → repository/content/atlas
vault/Hacksidian/playground → repository/content/playground
```

Если у существующего плагина настроены другие пути `atlasFolder` и `coloringsFolder`, ссылки создаются по ним. Уже существующие правильные ссылки сохраняются. Обычная папка, файл или ссылка на другой источник на месте назначения останавливают установку до изменения плагина. Автоматического удаления или переноса таких данных нет.

После установки открыть vault в Obsidian: материалы уже доступны, дополнительная кнопка загрузки не нужна. Правки сразу меняют исходники в `content/`. Из репозитория можно проверить `git diff`, сделать commit и push. Установщик не выполняет Git-команды.

Пути ссылок абсолютные. При переносе репозитория ссылки потребуется пересоздать. Не включать синхронизацию этих папок другим vault или Obsidian Sync. Не удалять материалы через Obsidian, если не нужно удалить соответствующие исходники. Внутри `.obsidian` ссылки не создаются.

Ссылки ведут на две внешние непересекающиеся папки. См. [ограничения символических ссылок в Obsidian](https://obsidian.md/help/symlinks). Фильтр дайджестов вычисляет папку приёмов относительно `this.file.folder`, используя [синтаксис Bases](https://obsidian.md/help/bases/syntax), без авторского абсолютного пути.

## Обновление

Изменения материалов в рабочей копии сразу доступны через ссылки. Для обновления кода плагина повторить `install:vault` при закрытом Obsidian. Устаревший файл `content.json.gz` удаляется из устанавливаемой копии плагина; старые отчёты и резервные копии сохраняются. Плагин больше не использует их для обновлений.

## Проверка и сборка

```sh
npm --prefix plugin run check
npm --prefix plugin run release:prepare
```

Проверяются типы, сборка и тесты. Тесты установки работают с временными vault. Правки через ссылки проверяются на отдельных временных исходниках, не на пользовательских данных.

`build/release/` содержит только три файла плагина. GitHub Actions сохраняет их как artifact, но ничего не публикует. Обычная установка из GitHub не создаёт ссылки на локальный репозиторий: пока нужно пользоваться локальным `install:vault`. Проверка интерфейса и индексирования в живом Obsidian выполняется отдельно.
