# Локальная установка: плагин и две символические ссылки

Эта инструкция описывает установку плагина в существующий vault из локальной копии репозитория. Готовый шаблон vault не требуется. Материалы подключаются ссылками. Для установки и обновления трёх файлов плагина из GitHub Release используйте [инструкцию выпуска плагина](plugin-release.md). Обновление плагина не обновляет атлас и песочницу; пользователь обновляет их отдельно.

## Установка

Закрыть Obsidian. Выбрать отдельный существующий vault вне репозитория. Из корня репозитория выполнить:

```sh
npm --prefix plugin ci
HACKSIDIAN_VAULT="/absolute/path/to/vault" npm --prefix plugin run install:plugin
```

Путь к vault обязателен. `HACKSIDIAN_CONFIG_DIR` при необходимости задаёт папку конфигурации вместо `.obsidian`.

Установщик копирует файлы плагина (`main.js`, `manifest.json`, `styles.css`), сохраняет настройки и историю существующей установки и включает плагин. Для материалов создаёт ровно две ссылки:

```text
vault/Hacksidian/atlas      → repository/content/atlas
vault/Hacksidian/playground → repository/content/playground
```

Если у существующего плагина настроены другие пути `atlasFolder` и `coloringsFolder`, ссылки создаются по ним. Уже существующие правильные ссылки сохраняются. Обычная папка, файл или ссылка на другой источник на месте назначения останавливают установку до изменения плагина. Автоматического удаления или переноса таких данных нет.

После установки открыть vault в Obsidian: материалы уже доступны, дополнительная кнопка загрузки не нужна. Правки сразу меняют исходники в `content/`. Из репозитория можно проверить `git diff`, сделать commit и push. Установщик не выполняет Git-команды.

Пути ссылок абсолютные. При переносе репозитория ссылки потребуется пересоздать. Не включать синхронизацию этих папок другим vault или Obsidian Sync. Не удалять материалы через Obsidian, если не нужно удалить соответствующие исходники. Внутри `.obsidian` ссылки не создаются.

Ссылки ведут на две внешние непересекающиеся папки. См. [ограничения символических ссылок в Obsidian](https://obsidian.md/help/symlinks). Фильтр дайджестов вычисляет папку приёмов относительно `this.file.folder`, используя [синтаксис Bases](https://obsidian.md/help/bases/syntax), без авторского абсолютного пути.

## Обновление

Чтобы обновить код и служебные стили уже установленного плагина в конкретном vault, из корня репозитория выполните:

```sh
npm --prefix plugin run update:code -- /Users/op/vaults/hacksidian
```

Замените путь на нужный vault. Команда собирает плагин и заменяет `main.js` и служебный `styles.css`. Пользовательские CSS-сниппеты, настройки, `manifest.json` и символические ссылки остаются без изменений. После выполнения перезагрузите плагин в Obsidian.

Если сборка уже готова, можно вызвать скрипт напрямую:

```sh
node plugin/scripts/update-code.mjs /Users/op/vaults/hacksidian
```

Скрипт не запускает установщик или миграции. При последующей перезагрузке выполняется обычная логика запуска плагина.

При первом запуске плагин создаёт 25 пустых CSS-сниппета. Их включение не меняет оформление: правила добавляет пользователь, применяя приёмы или редактируя CSS. Существующие сниппеты и их состояние включения сохраняются; обновление не очищает ранее настроенное оформление.

Изменения материалов в рабочей копии сразу доступны через ссылки. Для обновления кода плагина повторить `install:plugin` при закрытом Obsidian. Устаревший файл `content.json.gz` удаляется из устанавливаемой копии плагина; старые отчёты и резервные копии сохраняются. Плагин больше не использует их для обновлений.

## Проверка и сборка

```sh
npm --prefix plugin run check
npm --prefix plugin run release:prepare
```

Проверяются типы, сборка и тесты. Тесты установки работают с временными vault. Правки через ссылки проверяются на отдельных временных исходниках, не на пользовательских данных.

`build/release/` содержит только три файла плагина. GitHub Actions сохраняет их как artifact, а по тегу версии создаёт черновик GitHub Release. `install:release` устанавливает скачанные файлы и создаёт такие же ссылки на материалы локального репозитория; `install:plugin` сначала собирает плагин из исходников. Оба режима сохраняют правильные ссылки и пути из настроек. Проверка интерфейса и индексирования в живом Obsidian выполняется отдельно.
