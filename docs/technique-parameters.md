# Параметры приёмов на CSS Variables

Параметры задаются в `recipe.css` рядом с собственными CSS Variables приёма. Отдельного JSON-описания и хранилища значений нет. Редактор полей один для отдельной карточки и карточки внутри категории; специального списка экспериментальных ID в коде нет.

```css
.markdown-preview-view, .markdown-source-view {
  /**
   * @parameter Межстрочный интервал
   * @label-en Line height
   * @type number
   * @default 1.5
   * @min 1.2
   * @max 2.5
   * @step 0.05
   */
  --hacksidian-example-leading: 1.5;
  --line-height-normal: var(--hacksidian-example-leading);
}
```

Комментарий `/** … */` должен непосредственно предшествовать единственному объявлению переменной `--hacksidian-*`. В имя включается ID приёма, чтобы переменные разных приёмов не пересекались. Область объявления выбирает автор CSS; она должна обеспечивать доступность переменной именно в месте использования. Штатные переменные Obsidian продолжают использоваться в реализации, но редактируемое значение принадлежит приёму.

Поля:

- `@parameter` — подпись; `@label-en` — необязательная английская подпись.
- `@type number` — число; `@unit` задаёт фиксированную единицу (`px`, `em`, `rem`, `%`, `ch`, `ms`, `s`, `deg`), без неё число безразмерное. `@min`, `@max`, `@step` ограничивают ввод. Шаг отсчитывается от min, при отсутствии min — от нуля.
- `@type select` — список; каждая строка `@option CSS-значение | Подпись | English label` задаёт один допустимый вариант. Например, `@option var(--text-accent) | Акцент | Accent`. Вариант может ссылаться на штатную переменную.
- `@type color` — выбор непрозрачного цвета `#RRGGBB`; сохраняется как CSS-цвет без кавычек. Общая проверка формы и чата отклоняет другие значения.
- `@type text` — короткая строка для CSS `content`; хранится в двойных кавычках с экранированием кавычек и обратных слешей. Это не поле произвольного CSS. `@maxlength` по умолчанию 40.
- `@default` — обязательное исходное CSS-значение для сброса. Для числа включает единицу, для строки — кавычки.

Значение объявления — текущий выбор пользователя. Корректный ввод сразу записывается через `Vault.process`: заменяются только байты значения выбранной декларации, остальной CSS и комментарии остаются прежними. Записи одного файла последовательны. При конкурентном изменении той же переменной редактор показывает ошибку, сохраняет чужое значение и позволяет повторить ввод. Ручные изменения остальных частей файла сохраняются.

Предпросмотр следит за `recipe.css`, поэтому после сохранения обновляется существующим механизмом (с его задержкой 150 мс). При ошибке ввода остаётся последняя корректная версия. Все открытые карточки читают один CSS-файл; отдельных постоянных черновиков нет.

«Включить» применяет актуальный CSS. Для уже включённого приёма есть отдельная кнопка «Обновить уже существующий стиль»: она заменяет только маркированный блок этого приёма и сохраняет соседние блоки и ручной CSS вне него. Ручные изменения **внутри заменяемого блока** заменяются CSS приёма. Выключение удаляет установленный блок и сохраняет значения в папке приёма. Повторное включение использует сохранённые значения. Сброс отдельного поля меняет источник и пример; применённый стиль обновляется отдельно.

Приёмы без аннотированных переменных работают как прежде. Добавление следующего параметризованного приёма требует изменения только его CSS и пояснений, без новой ветки UI. `hack.json` сохраняет формат 2. Автоматическая подстановка в селекторы, произвольные шаблоны и пресеты, подменяющие целые CSS-файлы, не используются.

## Первый набор

Страница `atlas/Эксперименты с параметризованными приёмами.md` встраивает четырнадцать существующих карточек с тегом `hacksidian_parameter_experiment`: `quote-dashed`, `note-dropcap`, `quote-corner-marks`, `text-system-uswds`, а также `image-e016`, `link-e014`, `table-e015`, `code-e011`, `list-e010`, `heading-e019`, `tag-e008`, `task-e09`, `hr-e070`, `callout-technical-round`. Исходный вид сохраняется при значениях по умолчанию.

USWDS пока предлагает числовой параметр интерлиньяжа, а не выбор между системами. Текущие системы различаются наборами селекторов и охватом заголовков: Carbon — H2, USWDS — H1–H4. Объединение систем требует отдельно привести их к общей CSS-структуре и доказать сохранение поведения всех вариантов. Это оставлено открытым; независимая проблема соответствия категории CSS-модулю не меняется.

Экспериментальный переключатель акцента палитры остаётся локальным контролом демонстрации; он не выдаётся за сохраняемый параметр приёма.

## Обновления и проверка

Поскольку значения находятся в исходном CSS, замена этого файла обновлением каталога или генератором заменит и значения. В текущем dev-vault атлас связан с репозиторием симлинком: выбор в карточке будет изменением рабочего дерева. Автоматической перегенерации экспериментальных файлов нет. Для последующих генераторов/обновлений понадобится явное сохранение значений аннотированных переменных; нельзя молча перезаписывать файл.

Проверки: `npm --prefix plugin run check`, `node tools/verify-card-format.mjs content/atlas`, `HACKSIDIAN_ATLAS="$PWD/content/atlas" node tools/verify-recipe-catalog.mjs`, `git diff --check`.

Тесты покрывают разбор метаданных, границы чисел, допустимые варианты, экранирование строк, точечное сохранение, очередь записей и конфликты, два редактора, ошибки записи, сброс, отдельное обновление применённого блока и отсутствие побочных изменений других модулей. Проверка с моделями DOM/Obsidian не заменяет визуальную проверку в приложении.

Пользователь подтвердил, что первый набор работает в Obsidian. Для второй подборки (10 приёмов, 19 новых параметров) отдельно проверены сохранение исходных CSS-значений, редактирование параметров и изоляция предпросмотра; визуальная приёмка новых карточек остаётся за пользователем.

Поля настройки показаны без заголовка, после нижнего разделителя живого примера и перед пояснениями. Редактор живёт отдельно от обновляемого примера, чтобы сохранение CSS не сбрасывало фокус ввода. Избранное в карточках и списке использует одну SVG-звезду: серый контур для невыбранного состояния и зелёную заливку для выбранного.

## Настройка через чат

Откройте **саму страницу приёма**, затем напишите в чат, например, «Сделай линию толще» или «Увеличь межстрочный интервал до максимума». Модель видит текущие значения и ограничения тех же полей. Сохранённые значения появляются в форме и примере. Однозначная команда изменить оформление также включает приём или обновляет его установленный блок; при сомнении меняется только пример. Кнопка «Обновить уже существующий стиль» остаётся доступна.

На страницах категорий, подборок и экспериментов относительные команды вроде «сделай толще» пока не привязываются к встроенным карточкам — там работает поиск приёмов. При этом однозначный запрос на конкретный приём с желаемой настройкой может сразу преднастроить найденную карточку, как описано ниже. Если на карточке нет подходящего параметра, чат объяснит ограничение. Если запрос неоднозначен — уточнит. На самой карточке также можно попросить найти другой приём: запрос уйдёт в обычный поиск.

Чат не создаёт новых переменных или CSS-правил. Если во время ожидания поменять страницу или CSS, устаревшие изменения не запишутся. История показывает фактические значения до/после; расходы учитываются и при отклонённых ответах. Настройка параметров не требует поискового каталога; поиск другого приёма требует его и может использовать второй оплачиваемый запрос.


### Рекомендация с преднастройкой

Запрос «Я хочу, чтобы цитаты отбивались жирным пунктиром слева» может одновременно вернуть приём «Пунктир» и сохранить его параметры: рисунок `dashed`, толщина `4px` (вариант «Толстая»). Второй команды на заполнение формы не требуется. В ответе показаны фактические изменения и ссылка на карточку с готовым примером. При неясном намерении применить оформление установленный стиль не меняется.

В том же поисковом ответе модель возвращает ID рекомендации и список входных значений полей. Перед запросом приложение читает актуальные описания параметров локальных приёмов, присутствующих в каталоге; повторная синхронизация удалённого индекса ради параметров не требуется. Локальные данные задают допустимые поля, а найденные через file_search записи подтверждают выбор приёма.

Преднастройка разрешена только для единственной рекомендации с явно запрошенными настройками. Несколько альтернатив, неизвестные поля или недопустимые значения не записываются. Простая просьба показать, сравнить или объяснить приёмы не разрешает менять параметры. Изменившийся за время запроса CSS не перезаписывается.

При поиске вне карточки выбор и значения получаются за один API-запрос; второго параметрического запроса нет. На открытой карточке сохраняется существующая маршрутизация: если запрос касается другого приёма, сначала определяется переход к поиску, затем один поисковый ответ содержит и рекомендацию, и преднастройку. Эти вызовы по-прежнему учитываются в журнале расходов.


### Команда применения и открытие карточки

Для единственного найденного приёма чат отдельно определяет настройки и команду. «Сделай в ячейках таблицы отступы слева и справа как можно больше» означает table-e015, максимальные «Поля по бокам» и немедленное применение. Уже включённый приём обновляется в существующем блоке. Без новых настроек команда использует сохранённый CSS.

Если команда сомнительна, приём не включается. Единственный найденный приём показывается интерактивно в чате. Прямое применение и показ не открывают вкладку; она открывается только для уточняющего вопроса по одному проверенному приёму. Несколько результатов показываются списком без записи параметров, применения и переключения вкладок. На собственной странице приёма дополнительная вкладка не создаётся.

Команду интерпретирует модель только по текущему запросу и возвращает точную цитату основания; приложение проверяет её наличие в запросе. Это проверка происхождения команды, а не независимое доказательство её смысла. Автоматические тесты проверяют исполнение структурированных ответов; интерпретация живой моделью и поведение установленного интерфейса требуют проверки в Obsidian.


### Поиск после прерванного обновления каталога

Незавершённая синхронизация не запрещает поиск. Источниками служат файлы действующего снимка и сохранённого журнала загрузки того же удалённого индекса. Новые карточки доступны по мере индексации; неизвестные файлы отклоняются. Поиск не объявляет обновление завершённым. Пока сама операция обновления выполняется, общая блокировка операций сохраняется; после остановки и перезапуска приложения можно искать по доступным записям.

Обновление показывает «Обработано N из M файлов». Рядом со статусом в чате и настройках находится кнопка «Остановить». Она завершает текущий сетевой запрос, сохраняет результат загрузки и прекращает дальнейшие запросы. Повторное обновление использует сохранённый журнал.


### Карточки в результатах чата

Каждый найденный приём показывает изолированный живой пример и общий редактор параметров. Рядом с названием находятся звезда избранного и актуальная кнопка включения/выключения. Изменения источника обновляют пример; изменения избранного и установленного стиля синхронизируют кнопки. Компоненты освобождают подписки при обновлении истории и закрытии панели. Код и переключатель скрытия примера не выводятся. При невозможности встроенного предпросмотра показывается объяснение, поля параметров остаются доступны.

История не выводит версию каталога, токены под репликами, метку «Вы» и неизвестную стоимость. Сводка показывает число запросов и расходы; внутренний учёт usage сохранён. Ответы о параметрах ссылаются на название карточки. Текст панели можно выделять и копировать; фон реплик пользователя использует `--nav-item-background-active`.
