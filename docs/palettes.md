# Палитры

Категория `palette` использует существующий модуль `g-palette` и `hacksidian-00-palette.css`. В начальном наборе 12 источников и 26 вариантов. Существующие пустые установочные сниппеты остаются пустыми; ни одна палитра не включается автоматически.

## Данные и воспроизводимость

`tools/palettes/sources.json` — снимок значений из принятого интерактивного примера 17 сентября 2026. URL первоисточников и назначения цветов сохранены для каждого семейства. Material использует фиксированный seed `#6750A4` и `themeFromSourceColor`, Tailwind — Slate/Indigo, Radix — Slate/Iris; это наши конкретные сборки. Tinted представлен Default Light/Dark, а не всем каталогом. Недостающие pink/blue в отдельных источниках явно повторяют существующий цвет. Это адаптации, не официальные порты.

Снимок исходных значений остаётся неизменным при обычной сборке плагина. Отдельная команда:

```sh
node tools/palettes/build.mjs
```

создаёт карточки, CSS, Markdown, `hack.json`, `palette.json`, страницу категории и страницу проверки в playground. Она перезаписывает эти генерируемые файлы. Для добавления следующей палитры добавить семейство или вариант со стабильным уникальным `id` в `sources.json`, сохранить URL и происхождение ролей, выполнить генерацию и обновить сводный список в `atlas.md`. Галерея читает карточки из vault и не содержит жёсткого списка семейств.

## Контракт Obsidian

Каждый рецепт состоит из одного `body.theme-light` или `body.theme-dark`, содержит только штатные цветовые CSS-переменные, не меняет режим приложения, шрифты или геометрию. Базовая шкала из 12 ступеней строится из фонов, границ и уровней текста; промежуточные ступени — наша интерполяция OKLCH. Семантические роли и восемь цветов задаются явно. `-rgb` значения сохранены для старых потребителей; основные значения Tailwind остаются OKLCH.

Акцент намеренно не записывается: `--accent-*`, `--color-accent*`, `--text-on-accent*` и чёрно-белые `--mono-*` остаются под управлением Obsidian/темы. Выбор авторского акцента действует только внутри примера. Контраст кнопок внутри примера вычисляется локально; это не подмена алгоритма Obsidian.

`exclusiveGroup: palette-light` / `palette-dark` в `hack.json` и соответствующий маркер внутри CSS связывают заменяемые рецепты. При включении удаляется только полный блок предыдущей палитры того же режима. Палитра другого режима, ручной CSS и другие модули сохраняются. Повреждённые блоки вызывают ошибку до записи. Удалённая палитра не восстанавливается автоматически при выключении новой; история изменений использует штатный механизм плагина.

## Пример и проверка

Главная страница категории показывает все образцы подряд, сгруппированными по семействам: сначала светлые, затем тёмные варианты. Каждый образец имеет собственные кнопки включения и просмотра. Категория и отдельные карточки используют один `PaletteExample`. Он читает фактический `recipe.css`, проверяет договорённость о единственном селекторе и цветовых переменных и переносит значения на изолированный Shadow DOM. Светлый/тёмный пример не влияет на тему vault. Переключатель «Скрыть / Показать» сравнивает его с текущими цветами Obsidian. Все контролы примера локальны, не редактируют Markdown и не включают рецепт.

Типы, сборка и тесты: `npm --prefix plugin run check`. Дополнительно проверены точные копии CSS и повторное применение всех 1426 рецептов каталога. Цветовые переменные сверены с локальным `app.css` Obsidian 1.13.7. Собранный компонент отдельно проверен в браузере с этим CSS: все 26 вариантов, отсутствие влияния на окружающую страницу, контраст и таблица ролей. Это не подтверждает совместимость сторонних тем/плагинов или финальную отрисовку в живом Obsidian.
