# Подбор решений из атласа

Движок использует OpenAI Responses API и File Search. Он предлагает существующие решения, задаёт уточняющие вопросы или сообщает, что подходящего решения не нашёл. Чат не изменяет CSS. Применение и отключение приёма остаются в карточке. Команды Undo и переключения раскрасок удалены; история версий CSS больше не сохраняется.

## Использование

1. В настройках Hacksidian выберите модель OpenAI и укажите ключ с доступом к Responses, Files и Vector Stores. Ранее выбранная модель OpenAI сохраняется.
2. Проверьте путь к атласу и файлу глобальных переменных. Оба пути задаются относительно корня хранилища. Исходное значение файла переменных — `.obsidian/snippets/hacksidian-00-palette.css`; можно указать другой файл.
3. Нажмите **Обновить поисковый каталог** в панели, настройках или палитре команд. Дождитесь сообщения с количеством решений, версией и датой.
4. Задайте вопрос. Открытая заметка не требуется и не отправляется модели. Ответ содержит ссылки на карточки, инструкции для стандартных настроек или местоположение файла переменных. Инструкции применения приёмов и пути к стандартным настройкам формирует плагин из каталога; модель выбирает решения и объясняет соответствие запросу.
5. Примените выбранный приём из карточки. Переменные и стандартные настройки изменяются вручную.

Изменения атласа попадут в поиск после следующего обновления. Это позволяет отдельно редактировать атлас и экспериментировать с его фиксированной версией. История старых ответов сохраняется; в новый запрос включаются только последние шесть ходов этого движка с той же версией каталога. Предыдущие сессии генерации CSS в контекст не включаются.

## Что входит в каталог

Объяснения из пунктов «Зачем», «Как работает» и «Ограничения» включаются в поиск. Из актуального `recipe.css` сохраняются селекторы, названия свойств и их значения: например, `text-decoration-style: wavy` отличается от `dotted`. Встроенные data-URL заменяются обозначением без содержимого. Исторический CSS из карточки по-прежнему исключается. После установки обновлённой сборки перезагрузите плагин и нажмите **Обновить поисковый каталог**, чтобы эти данные попали в активный индекс.

- Карточки `atlas/! hacks/<id>/<id>.md` с тегом `hacksidian_technique`, их описания, ограничения, требования из `hack.json` в папке приёма, селекторы и значения свойств действующего `recipe.css`.
- Объявления CSS Variables из выбранного файла: имя, значение, селектор области действия и путь для ручного редактирования. Наличие переменной не означает, что она действует на весь интерфейс.
- Карточки `atlas/! themes/*.md` с тегом `hacksidian_theme`: автор, описание из Obsidian Community, режимы, проверенная ссылка на страницу темы и связи с приёмами. Поле `themes` содержит коды — имена страниц этой картотеки без `.md`. Неизвестный код останавливает обновление.
- Шесть проверенных стандартных настроек: акцентный цвет, цветовая схема, шрифт текста, размер шрифта, шрифт интерфейса, читаемая длина строки. Это начальный, не полный справочник настроек. Источник: [Obsidian Settings](https://obsidian.md/help/settings).

Исторические HTML/CSS, автоматически созданные отчёты и повторные объяснения из HTML-атласа не индексируются. Дайджесты, подбор плагинов и настройка параметров приёма пока не поддерживаются.

## Рекомендации тем

Для общего оформления или прямого запроса темы модель выбирает подходящую карточку темы из найденных записей и объясняет соответствие её описанию. Ссылки на карточку и Obsidian Community и инструкция ручной установки формируются приложением. Популярность не считается доказательством соответствия запросу.

У рекомендации приёма приложение дополнительно показывает темы из поля `themes`. Так продвижение установленных источников не зависит от того, вспомнит ли о них модель. Эти ссылки относятся к источникам и адаптациям, а не подтверждают наличие идентичного CSS в текущей версии темы. У приёма без связей тема не выдумывается. Плагин не устанавливает и не активирует темы.

Срез картотеки на 2026-09-16 после завершения разбора исходников: 100 тем по накопленным скачиваниям, 365 связанных приёмов и 1784 связи. Исследование добавило 179 информационных карточек и подтверждения для 137 прежних; его 1729 пар «приём — тема» охватывают 99 тем. Flexoki проверена отдельно: основной CSS содержит только палитры. Разобраны все 1889 переключателей и списков вариантов, включая 1266 настроек из прежней очереди; неразобранный остаток — 0. Прежние источники сохранены. Результаты, решения и границы проверки: `docs/research/theme-survey/README.md` и `atlas/! themes/_research/! обзор.md`.

Новые карточки помечены `implementation: theme-native`, `verification: source-only` и имеют `hasCss: false`: они объясняют возможности конкретных тем, условия, настройки и разметку. Это не проверенные независимые сниппеты. Движок включает их в поиск, но не предлагает применять отсутствующий CSS-рецепт. Переход на тему и установка требуемого плагина остаются ручными действиями.

Данные и проверенные Community URL: `tools/theme-catalog/themes.json`. Генерация: `node tools/theme-catalog/build.mjs /path/to/atlas`. Генератор сохраняет остальные метаданные, источники и тело каждого приёма; пользовательские связи сохраняются.

После установки новой сборки перезагрузите плагин и нажмите **Обновить поисковый каталог**: прежняя версия индекса не содержит тем. Само обновление локальных файлов не отправляет их в OpenAI.

## Обновление и ошибки

Каждая запись индексируется отдельным файлом: фрагменты поиска не смешивают разные приёмы. Имя файла стабильно и зависит от ID; версия каталога учитывает формат упаковки. Файлы добавляются в Vector Store партиями до 500 ([OpenAI Docs](https://developers.openai.com/api/docs/guides/retrieval)). Неизменённые файлы OpenAI используются повторно; изменённые загружаются заново. Новая версия индексируется в отдельном Vector Store. Рабочая версия переключается только после успешного завершения всей индексации. Ошибка оставляет предыдущую версию доступной.

Одновременно загружается не более четырёх файлов. Повторно используются исходные Files; новая версия Vector Store индексирует весь набор, поэтому даже небольшое обновление может потребовать ожидания. Созданные ресурсы записываются в журнал `catalog.pending` в данных плагина. Устаревшие хранилища и больше не используемые файлы удаляются; неудачная очистка повторяется при следующем обновлении. Обновление не затрагивает чужие хранилища OpenAI. Через 30 дней неактивности Vector Store истекает; повторное обновление создаёт новый.

Плагин проверяет, что рекомендованный ID присутствует в активной версии и найденных фрагментах. Ссылки строятся из локального каталога, а не из произвольных URL модели. Это не доказывает смысловую правильность рекомендации — качество подбора проверяется отдельно.

## Стоимость и диагностика

Сохраняются оплаченные попытки, включая ошибки разбора ответа; оценка включает токены и File Search. Тариф поиска: $0.0025 за вызов, проверен 2026-09-16. Хранение оплачивается отдельно по тарифу OpenAI и не входит в локальный лимит стоимости запросов. Свободный 1 ГБ относится ко всему аккаунту, а не к этому каталогу. [Тарифы](https://developers.openai.com/api/docs/pricing).

У каждого ответа сохраняются версия каталога, поисковые запросы, найденные ID и ID ответа OpenAI. Подробности доступны в `data.json` плагина; этот файл также содержит ключ API, поэтому не публикуйте его.

## Проверка разработки

```sh
npm --prefix plugin run check
node plugin/scripts/catalog-check.mjs
```

Вторая команда только читает локальный атлас и сохраняет отчёт в `/private/tmp/hacksidian-catalog-check.json`. Она использует настройки установленного плагина, не изменяя их. Пути можно переопределить переменными `HACKSIDIAN_VAULT` и `HACKSIDIAN_REPORT`.

```sh
node plugin/scripts/catalog-check.mjs --live
```

`--live` создаёт временный каталог OpenAI, выполняет шесть платных запросов и удаляет созданные облачные ресурсы. Ответы и расход сохраняются в отчёте, включая неуспешные попытки. Это проверка API отдельно от интерфейса Obsidian; она не заполняет рабочий каталог установленного плагина. Журнал временных ресурсов сохраняется рядом с отчётом; `cleanupPending` должен быть 0.

Для короткой проверки протокола после изменения инструкций можно добавить `--smoke`: будут взяты только реальная карточка скругления изображений и стандартная настройка акцентного цвета. Это не проверка полноты поиска по всему атласу.


Регрессионная проверка волнистых ссылок на полном временном каталоге:

```sh
node plugin/scripts/catalog-check.mjs --live --wavy-regression
```

Проверка проходит только если поиск возвращает `link-e023` и модель рекомендует его для вопроса «Какой приём делает ссылки волнистыми?». Использует API и сохраняет расход; рабочий индекс плагина не меняет. Временные файлы и хранилище удаляются после проверки.
