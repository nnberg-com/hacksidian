# Hacksidian: плагин CSS-груминга

Исходники: /Users/op/dev/olgapavlova/hacksidian/plugin. Установленная копия: /Users/op/vaults/op/.obsidian/plugins/hacksidian. Установщик переносит существующую установку Hacksidian с сохранением настроек и истории.

## Источник CSS

Образцовый набор находится в `snippets/` в корне репозитория: 22 файла `hacksidian-*.css` и `hacksidian-manifest.json`. Сборка встраивает их в плагин. Рабочие файлы находятся непосредственно в `${app.vault.configDir}/snippets` (для vault op — `/Users/op/vaults/op/.obsidian/snippets`). Префикс и числовая часть сохраняют группировку и порядок штатной загрузки Obsidian.

При первом запуске плагин создаёт только отсутствующие файлы, не перезаписывая существующие, включает свой набор и сохраняет `snippetsInstalled` в data.json. Последующие запуски и обновления не копируют шаблоны, не восстанавливают удалённые файлы и не меняют переключатели сниппетов. Изменение состава набора требует отдельной миграции. Сам проектный набор рабочий плагин не изменяет.

Плагин читает рабочие файлы при запуске, перед запросом и после ответа модели; раз в секунду обновляет внутренний контекст для ручных изменений. Ответ модели заменяет один файл после сравнения с исходным состоянием. Ошибки чтения или синтаксиса не восстанавливают файлы из data.json. В data.json сохраняются только настройки, отметка установки и история для Undo.

CSS применяет штатный менеджер сниппетов Obsidian: переключатели работают, отдельного style-элемента плагина и общего callmered-current.css нет. Интеграция с внутренним API Obsidian изолирована в src/snippets.ts.

Исходники раскрасок — `content/playground/ru/` и `en/` в репозитории. Локальный установщик создаёт в vault символические ссылки на папки атласа и песочницы в репозитории. plugin/templates — сохранённые тестовые образцы прежнего прототипа, не источник рабочего playground.

## Контекст модели

В настройках Hacksidian можно включить или выключить «Отправлять в LLM скриншот страницы» (по умолчанию включено), выбрать провайдера и модель и сохранить API-ключ. Доступны OpenAI, Anthropic (Claude), Google (Gemini) и xAI (Grok). Для каждого провайдера отдельно сохраняются ключ, модель и ручные тарифы. Блок «ID другой модели» виден и доступен только при явном выборе «Другая модель», включая после перезапуска.

«Автоматически рассчитывать стоимость» включено по умолчанию: тариф загружается с официальной страницы выбранной модели, сохраняется на 24 часа с источником и датой проверки. Ручные поля в этом режиме заблокированы. Кнопка «Обновить» обновляет тариф принудительно. Используются стандартные платные тарифы для текста/изображений; учитываются распознанные диапазоны длинного контекста и сроки акционных цен. При неизвестной модели, ошибке сети или изменении формата источника стоимость обозначается как неизвестная. Чтобы задать свои тарифы, выключите автоматический расчёт. Старые расходы не пересчитываются.

Источники: [OpenAI](https://developers.openai.com/api/docs/models), [Claude](https://platform.claude.com/docs/en/about-claude/pricing), [Gemini](https://ai.google.dev/gemini-api/docs/pricing), [Grok](https://docs.x.ai/developers/models). Парсеры цен проверены на сохранённых фрагментах официальных таблиц. Поддержка произвольных ID зависит от наличия распознаваемой строки/страницы тарифа; для Claude пока распознаются ID из встроенного списка.

OpenAI использует Responses API; Gemini и Grok — совместимый Chat Completions API. Для Claude применяется native Messages API с output_config.format, поскольку его совместимый слой игнорирует response_format. Все ответы проходят общую проверку структуры и CSS. Изменения настроек действуют со следующего запроса.

При включённой галочке плагин снимает текущий Reading view и передаёт изображение модели вместе с текстом пользователя, Markdown, CSS-модулями, вычисленными стилями и историей разговора. При выключенной — снимок не создаётся и не отправляется. Снимок существует только в памяти: на диск и в историю ходов не записывается. Захвата «после», ручной команды камеры и предпросмотра нет. История разговора хранится только в data.json плагина.

## История и текущая граница Undo

Кнопка «Очистить историю» в настройках удаляет весь чат и все прошлые шаги Undo. Текущий CSS, модель, ключи и остальные настройки сохраняются. Очистка недоступна до завершения выполняющегося запроса или Undo.

История CSS и ходы разговора хранятся только в `.obsidian/plugins/hacksidian/data.json`. Каталог CallMeRed в заметках больше не используется; старая структура Style удалена. Исходный data.json сохранён в vault в migration-backup/callmered-obsidian; он содержит локальные настройки и ключ, поэтому не предназначен для публикации.

История CSS ограничена 50 шагами Undo: текущая версия и не более 50 предыдущих. При запуске, сохранении и новом изменении старые версии удаляются из данных плагина. Журнал разговора сохраняет текст и статистику без копий CSS.

Undo работает внутри новой структуры, включая восстановление после перезапуска. У границы со старой структурой команда сообщает о начале истории текущего набора и не меняет файлы. Поддержка отката в старую структуру исключена по решению пользователя. Ручная правка также не перезаписывается Undo автоматически. Git пока не подключён и не является условием автономности. Старые команды миграции монолитного CSS сохранены как текст в scripts/legacy. Текущая verify-modular-runtime.js проверяет только файлы новой структуры.

## Сборка и установка

Актуальный порядок поставки, установки атласа и песочницы: [Установка плагина и материалов](../content-installation.md).

`npm run check` — типы, тесты и сборка. `npm run install:vault` устанавливает в явно заданный `HACKSIDIAN_VAULT`; HACKSIDIAN_CONFIG_DIR задаёт нестандартную папку настроек. При первом запуске создаются отсутствующие сниппеты. Для загрузки новой сборки перезагрузите установленный плагин в Obsidian.

Сохранённая конфигурация старого vault callmered больше не включает плагин. Это не выгружает экземпляр, если старый vault прямо сейчас открыт. Проверка полного цикла и LLM-вызов отложены пользователем.

## Приёмы атласа

Правило структуры — одна группа, один базовый сниппет, один набор переменных. См. [Базовые сниппеты](snippets.md). Открытая карточка с тегом `hacksidian_technique` и локальным `hack.json` показывает кнопку «Применить hack» в чате. Добавляется один блок CSS в связанный файл, без обращения к LLM; повторное применение не дублирует блок. Операция входит в общую историю Undo (50 шагов). Все шаблоны и их параметры остаются в каталоге приёма.

## Локализация

Язык интерфейса: автоматически как в Obsidian, русский или английский. Неподдерживаемый язык Obsidian заменяется английским. Минимальная версия Obsidian — 1.8.7. Язык контента выбирается независимо; по умолчанию совпадает с интерфейсом. Навигация использует выбранную подпапку ru/ или en/.

Чат отвечает на языке вопроса; при неопределённом языке — на языке интерфейса. История и язык документа сохраняются. Подробности: [Локализация](localization.md).

## Установка и смена идентификатора

Перед обновлением закройте Obsidian полностью, затем выполните:

```sh
npm --prefix /Users/op/dev/olgapavlova/hacksidian/plugin run install:vault
```

Установщик определяет прежнюю установку по имени Hacksidian в манифесте. Он переносит её в `.obsidian/plugins/hacksidian`, сохраняет `data.json` и остальные дополнительные файлы без изменения содержимого, обновляет список включённых плагинов, горячие клавиши и ссылки в конфигурациях рабочего пространства. Рабочие CSS-сниппеты не изменяются. Если одновременно найдены прежняя и новая установки, перенос останавливается до любых изменений. После установки запустите Obsidian.

## Рецепт без преобразований

Для нового формата `hack.json` содержит `format: 2`, `target` и `hasCss`.
Единственный источник CSS — `recipe.css` рядом с карточкой. Атлас включает его
без подстановок в iframe; плагин записывает то же содержимое в блок целевого
сниппета. Повторное применение обновляет этот блок через обычную историю Undo.
Рабочий CSS при этом не встраивается в сборку плагина.

Все 1 411 приёмов переведены на этот формат. У 1 389 есть CSS, у 22 файл
пустой: это примеры разметки. Дополнительный класс подключения заметке не нужен;
семантические классы и элементы, необходимые самому приёму, сохраняются. Разметка и классы атласа согласуются
с Obsidian, а не компенсируются отдельной версией CSS.
