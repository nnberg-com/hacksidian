# Генератор HTML-атласа

Python CLI читает Obsidian-картотеку и создаёт самостоятельный статический сайт.
Исходные файлы картотеки не изменяются. Старый HTML-атлас и migration-report.json не используются.

## Запуск

Из /Users/op/dev/olgapavlova/hacksidian:

```sh
python3 -m venv .venv-atlas
.venv-atlas/bin/pip install -r atlas_generator/requirements.txt
.venv-atlas/bin/python -m atlas_generator check
.venv-atlas/bin/python -m atlas_generator build
.venv-atlas/bin/python -m atlas_generator serve --port 8765
```

Открыть http://127.0.0.1:8765/. Виртуальное окружение и первая сборка уже созданы.
После изменения картотеки достаточно повторить build и обновить страницу.

По умолчанию источник: /Users/op/vaults/op/! P R O/hacksidian/atlas.
Результат: build/atlas относительно репозитория; текущая директория запуска не влияет на эти пути.

```sh
.venv-atlas/bin/python -m atlas_generator build --source "/path/to/atlas" --output "/path/to/result" --lang ru
```

check проверяет данные и локальные зависимости, не создавая сборку. serve раздаёт уже готовую сборку только на localhost.
index.html можно открыть и непосредственно с диска: данные поиска подключаются локальным JS без fetch.
Воспроизведение отдельных внешних ресурсов зависит от сети и ограничений браузера.

## Входные данные

- ! hacks/<ID>/<ID>.md — общие технические YAML-метаданные и ссылки на локализации.
- ! hacks/<ID>/Description.ru.md и Description.en.md — название, подпись группы и описание на выбранном языке. Незавершённый перевод помечается `translation_status: pending`.
- ! hacks/<ID>/Markdown.ru.md — актуальный пример.
- ! hacks/<ID>/recipe.template.css — CSS-шаблон приёма.
- ! hacks/<ID>/hack.json — группа, целевой сниппет и параметры шаблона для атласа и Obsidian.
- ! hacks/<ID>/dependencies.template.css — переменные и анимации, нужные рецепту.
- ! hacks/<ID>/preview.css — дополнительное оформление старого демонстрационного примера.
- ! hacks/<ID>/Model.ru.html и Model.css — необязательная сохранённая HTML-модель.
- ! hacks/<ID>/assets/ — локальные ресурсы.
- ! categories/<category>.md — названия категорий и общие источники.

Обязательные поля общей карточки: category, format, interactive (YAML boolean). `title` и текстовая подпись `group` находятся только в Description.<lang>.md. В описании обязательны `language` и непустой `title`; статус `pending` запрещает сборку этого языка.
format: markdown, html или properties. ID берётся из имени папки.
--lang выбирает Markdown.<lang>.md и Model.<lang>.html. --ui-lang выбирает оболочку, Description.<lang>.md, названия категорий и дайджестов. Отсутствующий или незавершённый перевод вызывает ошибку до замены прошлой сборки.

Без аргументов языки берутся из настроек установленного плагина: он сохраняет разрешённый язык Obsidian в `localization.interfaceLanguage` своего data.json. `contentLanguage: auto` следует языку интерфейса. При отсутствии настроек используется английский. `--standalone` отключает тему, но сохраняет выбор языка.

## Результат

Поиск по названию, ID, описанию, примеру и CSS; фильтры по категории, формату и interactive.
Справа — лента всех результатов фильтра: карточки добавляются по восемь при прокрутке, содержимое загружается рядом с видимой областью. Нажатие слева прокручивает ленту к выбранному приёму.
Оба списка используют один порядок; текущая карточка ленты подсвечивается в навигации.
На широком экране демонстрация находится слева, описание и исходники — справа; на узком экране колонки идут друг под другом.
Источники берутся из YAML и разделов Markdown карточки и категории; локальные пути происхождения отображаются текстом.
Высота карточек обновляется при раскрытии исходников; сами демонстрации сохраняют изоляцию в iframe.
Каждый приём также имеет отдельную страницу, исходники и ссылки на источники.
Ссылка «Открыть этот приём в Obsidian» открывает исходную заметку картотеки в новой вкладке Obsidian через `obsidian://open` с `paneType=tab`. Абсолютный путь заметки берётся из текущего источника сборки; после переноса картотеки нужна повторная сборка.
CSS одного приёма не влияет на соседние карточки или навигацию.
Встроенный preview сохраняет origin (`allow-same-origin`), чтобы локальные изображения и стили загружались также при открытии атласа через `file://`. Это сгенерированный документ: скрипты и обработчики событий из примеров удаляются рендерером; вложенные исходные iframe сохраняют отдельный sandbox.
Сохранённая модель доступна отдельно; для properties её структура используется с актуальными YAML-значениями.

build-report.json содержит количества, версии зависимостей и хеши входных файлов.
Сборка сначала готовится во временной папке. При ошибке предыдущий результат сохраняется.
Перезапись разрешена только для результата этого генератора с его маркером; каталог источников защищён.

Правила рендеринга описаны в [Контракте рендеринга](renderer.md) и закреплены тестами:

```sh
.venv-atlas/bin/python -m unittest discover -s atlas_generator/tests -v
```

Это браузерная демонстрация. Она не запускает Obsidian, его плагины или настоящий редактор CodeMirror.

## Оформление из Obsidian

```sh
.venv-atlas/bin/python -m atlas_generator build --obsidian-config /Users/op/vaults/op/.obsidian --output build/atlas-obsidian
```

Обычная команда build также автоматически использует тему vault. Этот режим читает настоящий `app.css` из установленного Obsidian, текущую тему и включённые сниппеты из `appearance.json`. Файлы Obsidian не меняются. Локальные ресурсы CSS встраиваются в один `obsidian.css`; хеши источников записываются в build-report.json. `--obsidian-app` позволяет указать другой файл obsidian.asar.

Примеры получают класс `callmered-coloring`, а CSS рецепта — параметры `atlas` из собственного hack.json. Старое демонстрационное оформление preview.css в этом режиме не подключается. Для всех карточек используется один снимок реального оформления. После изменения темы, сниппетов или настроек нужна новая сборка. По умолчанию CLI находит конфигурацию Obsidian рядом с исходной картотекой и подключает оформление в основной build/atlas: оболочку, страницы приёмов и примеры. Для автономного оформления нужно явно передать --standalone.

Это повторное использование CSS, а не запуск Obsidian в браузере: CodeMirror, плагины, интерфейс приложения и точная структура Reading view здесь не воспроизводятся. Результат показывает реальный каскад, поэтому базовые `!important` могут перекрыть некоторые приёмы. Совпадение браузерного и нативного результата требуется проверять отдельно.

## Дайджесты / Digests

`category` — одна структурная группа; `digest` — список тематических подборок:

```yaml
category: task
digest: [todo, management]
```

У карточки может быть ноль (`digest: []`), один или несколько дайджестов. Отсутствующее поле читается как пустой список для совместимости; строка вместо списка, повторы и неизвестные ID отклоняются при check/build.

Реестр: `! digests/<id>.md`. ID — имя файла латиницей (строчные буквы, цифры, дефис; первая — буква). `title` содержит русское название, `title_en` — английское. Оба обязательны. Обзор находится в `! digests/! digests.md`. `digests.base` показывает состав текущей карточки дайджеста по `list(digest).contains(this.file.name)`; копирование карточки с новым именем не требует изменения запроса. См. [синтаксис Bases и контекст this](https://obsidian.md/help/bases/syntax).

Состав задаётся только в свойствах карточек приёмов. Начальные подборки — редакционный выбор из описаний приёмов, не автоматическое назначение всей категории. Редактирование `digest` обновляет Obsidian-подборку через Bases; для браузера после правки нужен build. Генератор не изменяет Obsidian-картотеку.

HTML: отдельный фильтр дайджеста с количеством приёмов; он пересекается с поиском, категорией, форматом и интерактивностью. Дайджесты также показаны под заголовком карточки. «Все дайджесты» включает и приёмы без дайджеста. Каждый приём отображается один раз независимо от количества дайджестов.

Для английских названий и новых элементов интерфейса дайджестов при русских примерах:

```sh
.venv-atlas/bin/python -m atlas_generator build --lang ru --ui-lang en --output build/atlas-en
```

Без `--ui-lang` используется язык примеров (`ru` либо `en`). Существующий интерфейс HTML-атласа пока русский; локализованы новые элементы дайджестов. Локализация плагина в `plugin/i18n` работает отдельно и не используется статическим Python-генератором. Карточки дайджестов в Obsidian двуязычные.

Проверка логики фильтра без браузерного рендеринга:

```sh
node atlas_generator/tests/digest-filter.cjs
```

Полная проверка в браузере добавлена в `tests/feed-browser.cjs` (требует Playwright, доступного Chrome и запущенного localhost-сервера).


## Постоянная ссылка на подборку

Под фильтрами находится ссылка «Постоянная ссылка на подборку» / «Permanent link to this collection». Её можно открыть отдельно, сохранить в закладки или скопировать через контекстное меню. Адресная строка также обновляется автоматически.

Параметры URL: `search`, `category`, `digest`, `format`, `interactive`. Например, `index.html?digest=todo` открывает дайджест задач. Пустые фильтры в адрес не записываются. Переходы к отдельным приёмам сохраняют фильтры и добавляют `#ID`; ссылка на подборку не привязана к текущей карточке. При открытии URL или навигации назад/вперёд фильтры восстанавливаются. Неизвестные значения выпадающих фильтров игнорируются.

Ссылка сохраняет условия отбора, поэтому после обновления картотеки её состав может измениться. Для `file://` ссылка привязана к местоположению сборки на этом компьютере; она не публикует атлас в интернете.


Прокрутка: браузерная оболочка и preview переопределяют глобальное `overscroll-behavior: none` из CSS Obsidian на `auto`. Внутренние области прокручиваются до своей границы, после чего колесо продолжает прокручивать внешнюю ленту. Локальные настройки прокрутки самих приёмов не переопределяются.

## Локализация карточек

Все 1395 русских карточек перенесены в Description.ru.md без потери текста. Общие CSS, hack.json, ресурсы, Markdown.ru.md и сохранённые модели не изменены. Английские Description.en.md созданы со статусом pending; английские примеры ещё не переведены. Поэтому полноценная английская сборка сейчас намеренно останавливается. Оболочка генератора переведена на русский и английский.

Проверить готовность переводов:

```sh
.venv-atlas/bin/python -m atlas_generator translations --output build/atlas-translations.json
```

В Description.en.md нужно задать `language: en`, `translation_status: complete`, `title` и при необходимости `group`; разделы: Purpose, How it works, Demonstration, Limitations of the original technique, Notes from the HTML atlas, Sources. Затем добавить Markdown.en.md. Технические поля category, digest, format, interactive, sources и template остаются в общей карточке. Названия категорий: title/title_en; названия дайджестов уже имеют такую же схему.

Кнопка открытия приёма ведёт в Description.<ui-lang>.md. Плагин читает технические параметры из общей карточки и hack.json; применение CSS работает на общей карточке и на любом Description.ru/en.md.
