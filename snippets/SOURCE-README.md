# Сниппеты для Reading view

Готовый CSS-набор, сохраняющий оформление CallMeRed, проверенное 10 сентября 2026 года. Только Reading view документов с классом `callmered-coloring`. Плагин для работы этих CSS-файлов не нужен.

## Состав

| Файл | Что настраивает |
| --- | --- |
| `00-settings.css` | Палитру, шрифты, размеры, отступы, линии, радиусы и связь с переменными Obsidian |
| `10-reading.css` | Основной текст, H1–H6, вводный H2 и ритм статьи |
| `20-links-and-highlights.css` | Ссылки, внешние стрелки, теги, выделения и inline code |
| `30-lists-and-tasks.css` | Списки, вложенность, маркеры и задачи |
| `40-quotes-and-callouts.css` | Цитаты и выноски с иконками и линиями |
| `50-tables.css` | Существующее оформление таблиц |
| `60-code.css` | Блоки кода и принятую синтаксическую палитру |
| `70-images.css` | Существующее скругление изображений |
| `80-footnotes.css` | Нумерацию, отступы, обратные ссылки и подсветку сносок |
| `90-hide-note-header.css` | **Необязательно:** скрывает свойства, встроенный заголовок и служебную шапку заметки |

Общий файл `00-settings.css` нужен каждому сниппету. Для одинакового контекста чтения используйте также `10-reading.css`. Файлы компонентов не требуют друг друга: все их общие переменные находятся в `00-settings.css`. Стили вложенных элементов добавляются соответствующими сниппетами: например, код внутри выноски оформляется файлом `60-code.css`.

`50-tables.css` и `70-images.css` сохраняют скромное существующее покрытие. Новые варианты таблиц, embeds, формул или Mermaid в рамках чистки не добавлялись.

## Набор для каждой раскраски

У каждой раскраски остаётся свой выбор файлов; общие настройки и оформление чтения накапливаются и используются повторно.

| Раскраска | К `00-settings.css` и `10-reading.css` добавить |
| --- | --- |
| Структура и типографика длинной статьи | `20-links-and-highlights.css` для выделений внутри заголовков |
| Ссылки и изображения в длинной статье | `20-links-and-highlights.css`, `70-images.css` |
| Списки и задачи в длинной статье | `30-lists-and-tasks.css` |
| Цитаты в длинной статье; Выноски | `40-quotes-and-callouts.css` |
| Таблицы в длинной статье | `50-tables.css` |
| Код в длинном тексте | `20-links-and-highlights.css`, `60-code.css` |
| Формулы и сноски в длинной статье | `80-footnotes.css`; формулы сохраняют оформление Obsidian |
| Диаграммы Mermaid в тексте | Отдельного нового оформления диаграмм в этом наборе нет |
| Длинная статья — общий результат | Все файлы `20`–`80` |

Если в раскраске есть дополнительные элементы, подключайте их оформление тоже. Это соответствие файлов текущим материалам, а не обязательный порядок прохождения раскрасок.

## Как пользоваться

1. Скопируйте CSS-файлы верхнего уровня этой папки в `.obsidian/snippets` нужного vault. Каталог `work` и `manifest.json` для использования не нужны.
2. В настройках внешнего вида включите общие настройки, оформление чтения и нужные компоненты. Для точного воспроизведения прежнего вида включите также необязательный файл `90`.
3. Используйте класс `callmered-coloring` в свойствах документов:

```yaml
cssclasses:
  - callmered-coloring
```

Не подключайте новый набор одновременно со старым `callmered-current.css`: иначе они будут конкурировать. В рабочем vault текущий плагин также применяет старый CSS через собственный элемент style; для самостоятельной проверки сниппетов его применение нужно отключить, например временно выключить плагин через Obsidian. При подготовке набора конфигурация плагина и активный сниппет не менялись.

Числа в именах файлов обозначают рекомендуемый порядок. Проверялся полный набор в порядке `manifest.json`.

## Где менять оформление

Начните с `00-settings.css`. Примеры настроек:

- `--cmr-font-text`, `--cmr-font-code` — семейства шрифтов;
- `--cmr-text-size`, `--cmr-line-height-body` — основной текст;
- `--cmr-h1-font-size` … `--cmr-h5-font-size`, `--cmr-h6-size` — размеры заголовков;
- `--cmr-page-gutter` — поле статьи;
- `--cmr-list-indent`, `--cmr-nested-list-gap` — списки;
- `--cmr-callout-icon-size`, `--cmr-callout-icon-stroke-width` — иконки выносок;
- `--cmr-radius-inline`, `--cmr-radius` — увеличенный и базовый радиус;
- `--cmr-table-gap`, `--cmr-footnote-number-space` — таблицы и сноски.

Цвета, которые нужны Obsidian как RGB-каналы, задаются один раз, например `--cmr-color-cyan-rgb: 8, 132, 155`. Обычный цвет автоматически получается через `rgb(var(--cmr-color-cyan-rgb))`. Остальные исходные цвета записаны в HEX. Ролевые переменные ссылаются на палитру; это позволяет отдельно настроить роль, не меняя исходный цвет.

Технические `0`, `none`, `inherit` оставлены непосредственно в правилах. Новые числовые настройки не заменяют их искусственными переменными.

## Что проверено

- Парсером проверены все файлы, область действия, наличие используемых переменных, отсутствие циклов и повторных объявлений общих настроек.
- В Obsidian сравнены 40 вычисленных свойств обычных элементов и `::before`, `::after`, `::marker` на десяти раскрасках, при ширинах контейнера 440 и 881 px, в трёх позициях прокрутки. Проверено 10 299 состояний элементов: отличий от старого CSS и изменений горизонтального переполнения не обнаружено.
- Число `!important` уменьшено с 258 до 247: убраны десять усилений шрифта и одна декларация, повторяющая эффект предыдущего `text-decoration: none`.
- Альтернативные DOM-селекторы, состояния hover, выполненные задачи и подсветка сносок сохранены. Остальные усиления не удалялись без доказательств. Отдельный полный перебор hover/focus/target и всех тем Obsidian не выполнялся.

Сравнение подтверждает сохранение проверенного вида, а не отсутствие всех старых проблем адаптивности. Проверка не заменяет пользовательскую оценку внешнего вида.

Исходный CSS, отчёты и вспомогательные скрипты находятся в `work/`. Скрипт `prepare.mjs` воспроизводит разовое преобразование старого набора; после ручных правок готовых CSS-файлов не запускайте его, иначе он заменит их исходным результатом преобразования.
